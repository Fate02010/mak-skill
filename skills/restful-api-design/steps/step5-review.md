# Step 5：汇总审视，提出改进建议

**目标：** 全面审视生成的接口文档，发现问题并提出改进建议；改进后用 Edit 工具补丁式更新，不全量重写。

## 阶段 5-1：四维度审视

> **上下文控制：** 读取 `WORK_DIR/接口文档.md` 进行审视，仅在需要核实资料时用 offset/limit 定位 RountMap 中的具体文件段落。

| 维度 | 检查要点 |
|------|---------|
| **完整性** | 资料中所有业务功能都有对应接口？分页/筛选/排序参数齐全？错误码覆盖主要异常场景？ |
| **规范性** | URL 含版本号？资源使用复数？HTTP Method 使用正确？每个接口标注幂等性？ |
| **一致性** | 相同语义字段命名一致？分页参数风格统一？响应结构一致？错误码格式统一？ |
| **可用性** | 入参说明清晰？示例值合理？出参字段含义明确？状态枚举值列出所有情况？ |

## 阶段 5-2：展示审视结果，等待确认

```
=== 接口文档审视报告 ===

【完整性】✅ / ⚠️ [问题：如缺少搜索接口]
【规范性】✅ / ⚠️ [问题：如 URL 缺少版本号]
【一致性】✅ / ⚠️ [问题：如部分接口用 page，部分用 pageNum]
【可用性】✅ / ⚠️ [问题：如状态枚举未列出所有值]

是否应用改进建议？（"全部应用" / "选择应用 1,3" / "不需要"）
```

## 阶段 5-3：应用改进

使用 `Edit` 工具对 `WORK_DIR/接口文档.md` 做**精确补丁修改**（只改受影响部分，禁止全量重写）：
- 新增接口 → 在对应模块末尾插入新接口章节
- 修改字段命名 → 精确替换对应行
- 补充枚举值 → 在对应表格行末尾追加

## 阶段 5-4：完成报告

```
=== 接口文档生成完成 ===
- [WORK_DIR]/接口文档.md  （共 N 个接口）
如需增量调整，下次启动选择增量模式（Step 6）。
```

## 改进循环

用户可继续提出改进需求，每轮用 `Edit` 补丁式更新；用户回复"完成"或"不需要"时终止。
