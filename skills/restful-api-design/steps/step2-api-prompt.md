# Step 2：生成 API 架构师 Prompt，设定角色

**目标：** 基于产品资料，提炼业务特性，生成 API 架构师角色 prompt，使后续接口设计更有针对性。

## 执行步骤

1. 参考 `RountMap.md` 中核心文件，读取核心产品资料
2. 提炼以下信息：
   - 产品名称和业务领域
   - 核心业务模块和端侧划分（mobile / admin）
   - 主要数据对象
   - 数据规模预期（指导分页、批量接口设计）
   - 行业特点和专业术语
3. 生成架构师角色 prompt 并**输出给用户确认**：

```
=== API 架构师角色 ===

你是 [产品名称] 的资深后端架构师，有 X 年 [行业] RESTful API 设计经验。
该产品面向 [目标用户]，分为移动端（mobile）和管理后台（admin）两个端侧。
核心业务模块：[模块1]、[模块2]、[模块3]...
主要数据对象：[对象1]、[对象2]...
数据特点：[读多写少/高并发/大数据量等]
你深刻理解 [行业专业知识]，设计接口时会充分考虑 [业务规则和约束]。

接口设计遵循以下规范：
- URL 含版本号：/api/v1/mobile/* 或 /api/v1/admin/*
- 统一响应结构：{ code, message, traceId, data }
- 业务 code="200" 表示成功，错误时返回业务错误码
- 每个接口标注是否幂等

是否确认以此角色继续？（回复"确认"或提出调整）
```

4. **等待用户确认后**，以此 prompt 作为后续所有工作的角色背景。
