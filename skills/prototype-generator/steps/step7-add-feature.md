# Step 7：新增功能原型（增量模式）

**触发场景：** 工作流已完成过一次，用户希望在现有原型基础上新增功能模块或页面，无需重跑完整流程。

---

## 阶段 7-1：理解新增需求

1. 请用户描述新增功能（若已提供则跳过）：

```
=== 新增功能确认 ===

请描述要新增的功能，可以是：
- 一句话描述（如"新增消息通知模块"）
- 具体功能点列表
- 直接粘贴需求文字

我会基于已有产品背景和竞品分析，补全完整需求后开始生成。
```

2. 读取 `WORK_DIR/requirements/详细需求文档.md` 了解现有功能边界，避免重复或冲突
3. 读取 `WORK_DIR/原型任务清单.md` 了解已有页面和跳转地图

## 阶段 7-2：补全新功能需求，用户确认

1. 基于用户描述，结合已有产品上下文，补全新功能的完整需求（参照 `SKILL_DIR/steps/step4-doc-format.md` 中的功能点格式）
2. 运行功能依赖检查（参照 `SKILL_DIR/steps/step4-requirements.md` 中的依赖模型），补全关联功能
3. 向用户展示新增功能清单确认：

```
=== 新增功能确认 ===

📦 新增模块：[模块名]
  • [功能 1]：[一句话说明]
  • [功能 2]：[一句话说明]
  • [功能 3]：[一句话说明（依赖补全）]

需新增原型页面：
  → [页面名1.html]：[说明]
  → [页面名2.html]：[说明]
  → [涉及修改的已有页面]：[需要在哪里添加入口/跳转]

是否确认？
- 回复"确认"：开始生成
- 回复"调整"：说明修改意见
```

4. **等待用户确认后**继续

## 阶段 7-3：更新需求文档

将新增功能写入 `WORK_DIR/requirements/详细需求文档.md`：
- 在"## 3. 功能模块清单"末尾追加新模块章节
- 在"## 7. 原型图清单"中追加新页面记录
- 末尾追加"## 变更记录"条目，注明新增时间和内容摘要

## 阶段 7-4：并行生成新增原型页面

1. 确认 OUTPUT_FORMAT：HTML 模式检查 `WORK_DIR/prototypes/` 下有 `.html` 文件；draw.io 模式检查有 `[产品名称].drawio`
2. 读取 `SKILL_DIR/steps/step5-agent-prompt.md` 获取提示词模板，按 OUTPUT_FORMAT 选择对应模板
3. 仅对新增页面启动并行子任务（已有页面不重新生成）
4. 向用户展示执行计划并确认，启动方式同 Step 5-3：
   - **Claude Code**：`Agent` 工具分批并行调用，每批最多 3 个子 agent
   - **Codex**：`spawn_agent` 分批并行启动子任务，每批最多 3 个子 agent
   > Claude Code 请参考 `SKILL_DIR/steps/claude-rules.md`；Codex 请参考 `SKILL_DIR/steps/codex-rules.md`。

## 阶段 7-5：修改受影响的已有页面 / diagram

新增功能往往需要在已有页面中添加入口，逐一处理：

**HTML 模式**：列出需要修改的 `.html` 文件（如导航栏、首页菜单），逐文件编辑，添加指向新页面的链接/按钮。

**draw.io 模式**：修改 `WORK_DIR/prototypes/[产品名称].drawio`：
- 在需要添加入口的 `<diagram>` 中追加新的跳转按钮 `<mxCell>`（含 tooltip 指向新页面 diagram name）
- 将新增页面的 `<diagram>` 元素追加到文件中

## 阶段 7-6：更新导航首页 / 目录 diagram

根据 OUTPUT_FORMAT 更新：
- **HTML 模式** → 重新生成 `WORK_DIR/prototypes/index.html`：在已有页面列表中追加新页面入口，更新跳转地图
- **draw.io 模式** → 修改 `[产品名称].drawio` 中的 `<diagram name="导航-页面跳转地图">`：追加新页面节点和连线

版本号 / 最后更新时间同步更新。
