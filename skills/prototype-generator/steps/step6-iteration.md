# Step 6：改进建议与迭代循环

所有原型图生成完毕后，进入改进建议环节。这个环节的目的是帮助用户发现原型中可以进一步打磨的方向，而不是强迫迭代——如果用户满意，随时可以停止。

## 阶段 6-1：自评与建议生成

完成所有原型后，从以下维度审视已生成的原型，列出 **3-5 条具体的改进建议**：

**审视维度：**
- **流程完整性**：是否有用户路径无法走通？是否有功能模块缺少关键状态（如加载失败、权限不足）？
- **交互细节**：是否有可以更流畅的过渡动效？表单校验是否足够友好？
- **内容真实性**：示例数据是否贴近真实业务场景？空状态是否有引导文案？
- **竞品对标**：竞品分析报告中提到的差异化亮点是否都在原型中体现？
- **边缘场景**：错误页、超时页、无权限页等异常状态是否覆盖？

**建议格式：**

```
=== 原型改进建议 ===

我在审视生成的原型后，发现以下可以进一步完善的方向：

1. [建议标题]
   问题：[当前原型的不足之处]
   改进：[具体怎么改]
   影响页面：[哪些 HTML 文件需要修改]

2. [建议标题]
   ...

是否需要继续改进？请告诉我：
- 回复"全部改"：按照以上所有建议改进
- 回复"改1,3"（数字）：只改指定建议
- 回复"不用了"：结束，保持现状
- 或者直接描述你有其他想法
```

## 阶段 6-2：执行改进

用户确认改进后：

1. 根据用户选择，确定要改进的建议列表
2. 对每个改进项，直接编辑对应的文件
3. 如果改进引入了新的需求决策，同步更新 `详细需求文档.md`
4. 在 `WORK_DIR/执行状态.md` 的"Step 6 迭代记录"中追加本轮摘要（轮次 + 改进内容摘要）
5. 当前迭代轮次 < 上限时，**再次进入阶段 6-1**，生成新一轮改进建议

**迭代上限：最多 5 轮**

每次进入阶段 6-1 时，在建议标题前显示当前轮次：

```
=== 原型改进建议（第 N / 5 轮）===
```

**循环终止条件（满足任意一条即终止）：**
- 用户明确表示满意（回复"不用了"/"好了"/"完成"等）
- 连续两轮建议都没有实质性改进点
- 用户主动中止
- **已达到第 5 轮上限**：主动告知用户并停止循环：

```
已完成第 5 轮改进（迭代上限）。
如需继续优化，请重新触发 Step 6，或在下次会话中继续。
```

将 `执行状态.md` 整体状态更新为"已完成"。

> **改进原则：** 每轮改进要聚焦、可执行，不要提出过于笼统的建议（如"整体优化一下"）。每条建议应指向具体页面的具体问题，让用户能快速判断是否值得改。
