## 2.5 系统边界与外部依赖

> **用途：** 这一节是开发和架构的共用输入，帮助后续 Agent 判断哪些能力属于本系统、哪些依赖外部系统，不得只写“对接 ERP/支付”而不说明方向和边界。

### 终端与系统边界

| terminal_type | 终端/系统 | 定位 | 主要职责 | 不负责内容 |
|----------|------|------|---------|-----------|
| `miniapp` | [如：小程序商城] | 用户交易端 | 浏览、下单、支付、售后、溯源查看 | 后台配置、角色授权 |
| `admin` | [如：后台运营台] | 运营管理端 | 商品、订单、会员、营销、内容配置 | 用户支付发起 |
| `app` | [如：司机端/员工端/App会员端] | 履约执行端或会员端 | 发货、签收、现场反馈 / 会员服务 / 业务处理 | 后台配置、跨终端运营配置 |
| `h5` | [如：营销活动 H5 / 报名页] | 移动 Web 传播端 | 分享、拉新、报名、浏览、转化 | 后台配置、深度履约操作 |
| `bigscreen` | [如：指挥中心大屏] | 态势展示端 | KPI、地图、告警、轮播场景、值班看板 | 复杂录入、后台配置 |
| `portal` | [如：品牌官网 / 业务门户] | 官网展示端或入口聚合端 | Hero 展示、方案案例、门户快捷入口、消息待办 | 后台配置、工控操作 |
| `industrial` | [如：产线工控机/HMI] | 现场触控操作端 | 设备监控、流程控制、报警处置、参数查看 | 品牌展示、后台运营配置 |

> **终端命名规则：** `admin→后台`、`miniapp→小程序`、`app→App`、`h5→H5`、`bigscreen→大屏`、`portal→官网门户`、`industrial→工控机`。后续 `page_model.module_name` 必须使用 `[terminal_name]-[业务模块]` 格式。

### 外部依赖清单

| 外部系统/能力 | 接入方式 | 本系统输入 | 本系统输出 | 失败影响 |
|--------------|---------|-----------|-----------|---------|
| [如：微信支付] | API/SDK | 支付单、金额、用户标识 | 支付结果、退款结果 | 订单状态不可推进 |
| [如：ERP] | API/文件同步 | 商品/批次/库存/组织数据 | 同步结果、对账状态 | 数据延迟、状态不一致 |
| [如：短信/消息] | API | 手机号、模板参数 | 发送结果 | 通知失败但业务主流程不一定中断 |

> **质量标准：**
> - 每个功能点必须填写**开发关注点、权限与可见范围、数据影响**三个区块，这是开发和架构的最小输入
> - overview 必须包含 `§2.5 系统边界与外部依赖`、`§2.8 模块职责与协作关系`；有后台时必须包含 `§3.6 后台导航结构`
> - 列表页：筛选条件逐个列出（含控件类型、枚举值、数据来源）；表格列逐列列出（含排序、操作列说明）；分页规则写明默认条数和排序字段，并补充导出/批量操作/按钮前置条件
> - 表单页：每个字段一行，列出控件类型、是否必填、校验规则（长度/格式/唯一性等）、占位提示；并补充字段来源、编辑权限和提交副作用
> - 详情页：明确展示字段列表、状态流转、各状态下可操作的按钮，以及关键异常态
> - **页面类型**：必须从以下选项中选择一个——列表页 / 表单页（独立页面）/ 表单页（弹窗）/ 详情页 / 独立页面 / 首页/Dashboard / 确认弹窗 / 其他
> - **页面原型类型**：必须从以下选项中选择最贴近的一项——`dashboard` / `list_table` / `detail_kv` / `form_page` / `modal_form` / `drawer_permission` / `dispatch_board` / `tree_manage` / `content_manage` / `audit_log` / `mobile_home` / `profile` / `login`
> - **导航归属**：移动端填 Tab 名称或 `无`；后台页填左侧菜单路径；独立页填 `无`
> - **主要字段数量**：列表页填 `N列`，表单/详情页填 `N字段`，弹窗填 `-`；供原型 Agent 评估复杂度和分配生成任务
> - 竞品参考应指明本产品的改进方向而非照抄
> - 文档应足够详细，让原型 subagent 无需猜测字段名、导航归属、规则展示重点和权限边界即可直接绘制
