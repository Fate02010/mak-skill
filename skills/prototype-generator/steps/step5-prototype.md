# Step 5：工作流——并行生成 HTML 原型图

这是核心步骤，分五个阶段执行。

## 阶段 5-1：读取需求，功能划分

1. 读取 `详细需求文档.md` 中的"原型图清单"
2. 将所有需要生成的页面按功能模块分组
3. 估算每个页面的复杂度（简单/中等/复杂）
4. **绘制页面跳转地图**：梳理所有页面之间的跳转关系，确保每条用户操作路径都有对应的目标页面。如果发现某条流程缺少承接页面（例如点击"提交"后无结果页），立即补充到任务清单中。
5. 输出功能划分结果到 `原型任务清单.md`

## 阶段 5-2：拆分生成任务

将原型页面拆分为独立的生成任务，每个任务包含：
- 页面名称和文件名
- 需求文档中对应的章节标题（供 subagent 自行 Read，不在提示词中嵌入内容）
- **完整的进出跳转关系**：该页面从哪些页面跳入、点击哪些元素跳转到哪些页面（用文件名指定）
- 视觉风格要求

将任务清单写入 `原型任务清单.md`：

```markdown
# 原型图生成任务清单

## 页面跳转地图
[用箭头描述完整的页面流转，确保无断头路]
登录页 → 首页 → 详情页 → 确认页 → 成功页
首页 → 个人中心页
...

## 任务列表
- [ ] 任务1：[页面名称] → 输出文件：prototypes/[文件名].html
      进入来源：[来源页面]  跳出去向：[目标页面及触发元素]
- [ ] 任务2：[页面名称] → 输出文件：prototypes/[文件名].html
      进入来源：[来源页面]  跳出去向：[目标页面及触发元素]
...

## 共用配置
- 设计风格：[从产品资料中提炼的设计风格]
- 主色调：[颜色]
- 过渡动效：[页面切换方式，如 slide/fade/push]
```

## 阶段 5-3：按模块并行启动 subagent 生成 HTML 原型图

### 启动前：向用户展示执行计划

在启动任何 Agent 之前，**必须先向用户展示本次并行任务分配计划**，格式如下：

```
=== 原型生成执行计划 ===

共 N 个功能模块，将启动 N 个并行 Agent 分模块生成：

┌─────────────────────────────────────────────────────┐
│ Agent-1  [权限管理模块]                               │
│   负责页面：登录页、角色管理页、人员管理页、权限配置页    │
│   页面数量：4 页（3 简单 + 1 复杂）                    │
├─────────────────────────────────────────────────────┤
│ Agent-2  [订单管理模块]                               │
│   负责页面：订单列表页、订单详情页、退款申请页           │
│   页面数量：3 页（2 简单 + 1 复杂）                    │
├─────────────────────────────────────────────────────┤
│ Agent-3  [商品管理模块]                               │
│   负责页面：商品列表页、商品编辑页、分类管理页           │
│   页面数量：3 页（全部中等）                           │
└─────────────────────────────────────────────────────┘

输出目录：[WORK_DIR]/prototypes/
预计生成：N 个 HTML 文件

确认后将同时启动以上 N 个 Agent。
```

**等待用户确认后**，再执行并行启动。

### 分模块规则

- **一个功能模块 → 一个 Agent**，Agent 名称用模块名标识
- 每个 Agent 只负责本模块的所有页面，不跨模块
- 单模块页面超过 6 页时，拆分为 2 个 Agent（各负责一半）
- 最多同时启动 **6 个并行 Agent**

### 启动 Agent 的方式

**根据当前运行环境选择对应方式，两种方式使用完全相同的提示词：**

**Claude Code**：使用 `Agent` 工具，在单次响应中同时调用所有 Agent（实现真正并行）。

**Codex**：使用 `Task` 工具并设置 `run_in_background=true`，为每个模块启动一个后台 Task，再统一用 `TaskOutput` 收集结果。

每个 Agent / Task 的提示词如下：

```
你是 [模块名] 的原型生成 Agent。

先读取 [SKILL_DIR]/steps/html-spec.md 获取 HTML 原型规范，然后生成以下页面。

【工作目录】
WORK_DIR = [WORK_DIR的绝对路径]
所有文件必须保存在 WORK_DIR/prototypes/ 下，严禁写入 /private/tmp 或其他系统临时目录。

【本模块负责的页面】
1. [页面名称1] → 保存为 prototypes/[文件名1].html
2. [页面名称2] → 保存为 prototypes/[文件名2].html
...

【需求文档】
Read WORK_DIR/详细需求文档.md 中以下章节获取各页面需求（不要读取整个文档）：
- [页面名称1] → 章节：[### 模块名 > #### 功能点名]
- [页面名称2] → 章节：[### 模块名 > #### 功能点名]

【页面跳转关系】
- [页面名称1]：从 [来源页.html] 跳入，[按钮A] → [目标页A.html]，[返回] → [来源页.html]
- [页面名称2]：从 [来源页.html] 跳入，[按钮B] → [目标页B.html]

【设计风格】[风格]，主色调：[颜色]

【需求变更记录要求】
发现假设决策/遗漏/新增时，在对应 HTML 文件末尾追加注释：
<!-- REQUIREMENT_CHANGES
[变更类型: 假设/遗漏/新增]
页面: [页面名]
描述: [具体内容]
建议更新需求文档: [章节及建议]
-->

所有页面生成完毕后，输出一行汇报：
"✅ [模块名] 完成，生成 N 个文件：[文件名1.html, 文件名2.html, ...]"
```

### 启动后：实时显示进度

所有 Agent 启动后，向用户展示等待状态：

```
已启动 N 个并行 Agent，正在生成中...

⏳ Agent-1  [权限管理模块]  生成中...
⏳ Agent-2  [订单管理模块]  生成中...
⏳ Agent-3  [商品管理模块]  生成中...

等待所有 Agent 完成后进入下一步。
```

每个 Agent 完成时，将对应行更新为 `✅ Agent-X  [模块名]  已完成（N 个文件）`。

## 阶段 5-4：收集需求变更，更新需求文档

所有并行任务完成后，**在生成导航首页之前**，执行以下操作：

1. 读取所有生成的 HTML 文件，提取其中的 `<!-- REQUIREMENT_CHANGES ... -->` 注释
2. 汇总所有变更记录，判断哪些需要同步回需求文档：
   - **假设性决策**：如果假设合理，更新需求文档将其固化为正式需求
   - **需求遗漏**：补充到需求文档对应章节（功能点、流程、原型图清单等）
   - **主动新增**：在需求文档原型图清单中补充新增页面
3. 直接编辑 `详细需求文档.md`，将变更同步进去（在文档末尾追加"变更记录"章节，说明本次更新内容和原因）
4. 将汇总的变更内容记录到 `原型任务清单.md` 末尾的"需求变更汇总"区块

## 阶段 5-5：生成导航首页

所有子任务完成、需求文档更新后，生成 `prototypes/index.html`：
- 列出所有已生成的原型页面，附一句功能说明
- 提供直接跳转链接
- 显示产品名称和版本信息
- 以可视化方式展示页面跳转地图（用简单的箭头连线 HTML 表示）
