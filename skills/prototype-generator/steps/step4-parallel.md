# 大型需求文档并行分块编写流程

> **触发条件：** 模块数 > 3 或预估文档行数 > 300 行时加载本文件。
>
> **核心变化：** 大型项目需求文档**不再合并为单一大文件**，而是拆分为 1 个共用 overview 文件 + N 个模块文件，永久保留。这样 Step 5 每个 subagent 只需加载 overview + 自己的模块文件，上下文缩减约 70%。

---

## 文件结构约定

```
WORK_DIR/
└── requirements/
    ├── 详细需求文档_overview.md        ← 共用部分（用户角色、核心流程、数据模型、原型图清单）
    ├── 详细需求文档_[模块中文名].md    ← 每个模块一个文件，只含该模块的功能点+字段规格
    ├── 详细需求文档_[模块中文名].md
    └── ...
```

> **注意：** 不生成合并版 `详细需求文档.md`。所有后续步骤（Step 5、Step 6）通过读取 overview + 对应模块文件获取完整信息。

---

## 步骤一：生成共用 overview 文件

主进程直接生成 `WORK_DIR/requirements/详细需求文档_overview.md`，包含以下章节（**不含**功能模块清单 §3）：

```markdown
# [产品名称] 详细需求文档 — Overview

## 1. 产品概述
## 2. 用户角色
## 3.5 移动端导航结构（有移动端 App/小程序时必填）
## 4. 核心业务流程
## 5. 数据模型与状态
## 5.5 枚举值字典
## 6. 非功能需求
## 7. 原型图清单
```

> **§3.5 移动端导航结构** 必须在 overview 中，因为所有模块的移动端 subagent 都需要知道哪些页面有底部 Tab Bar。
> **§7 原型图清单** 必须在 overview 中，包含所有模块的页面，含页面类型、是否主导航页、主要字段数量三列。
> **§5.5 枚举值字典** 必须在 overview 中，跨模块共用的状态枚举值集中在此定义。

---

## 步骤二：并行生成各模块文件

将所有模块分配给并行 Agent，每个 Agent 负责 1-2 个模块（Codex 建议每个 Task 1 个模块）。

每个模块独立输出为 `WORK_DIR/requirements/详细需求文档_[模块中文名].md`，只含该模块的 §3 内容：

```markdown
# [产品名称] — [模块名]需求

## 3. 功能模块清单 — [模块名]

### [模块名]

#### 功能点 X.1：[功能名称]
...（完整字段规格、三态设计、验收标准）
```

**Agent / Task 提示词模板：**

```
编写以下模块的需求文档，保存为 [WORK_DIR绝对路径]/requirements/详细需求文档_[模块中文名].md。

【写作范围】只写该模块的"## 3. 功能模块清单"内容，包含完整字段规格：
- [模块名]：[功能点列表]

【参考资料】
- Read [WORK_DIR绝对路径]/requirements/详细需求文档_overview.md 第2章"用户角色"和第5.5章"枚举值字典"（了解角色定义和状态枚举值）
- Read [WORK_DIR绝对路径]/竞品分析报告.md 中 [模块名] 相关章节（获取竞品洞察）

【格式】严格遵循 step4-doc-format.md 中功能模块清单的结构，每个功能点必须包含：
- 字段规格区块（▌列表/查询页字段规格 / ▌新增/编辑表单字段规格 / ▌详情/状态页字段规格）
- 三态设计表格（▌三态设计）
- 可见角色字段

【自查规则】每写完一个功能点，检查是否有对应字段规格区块和三态设计；缺少则立即补全后再继续下一功能点。

完成后输出：✅ requirements/详细需求文档_[模块中文名].md 完成，N 个功能点，M 行。
```

**Claude Code（Agent 工具）：**

```
Agent(prompt="...模块1 完整 prompt（所有占位符已替换）...")
Agent(prompt="...模块2 完整 prompt（所有占位符已替换）...")
...  # 所有调用在同一响应中发出，并行执行
```

**Codex（Task 工具）：**

```python
task_1 = Task(prompt="...模块1 完整 prompt...", run_in_background=True)
task_2 = Task(prompt="...模块2 完整 prompt...", run_in_background=True)

result_1 = TaskOutput(task_id=task_1.id, block=True, timeout=300000)
result_2 = TaskOutput(task_id=task_2.id, block=True, timeout=300000)
# 成功标志：输出包含 "✅ 详细需求文档_[模块中文名].md 完成"
```

---

## 步骤三：验收与生成索引文件

所有模块文件生成后：

1. **完整性验收：** 用 `Glob WORK_DIR/requirements/详细需求文档_*.md` 列出所有文件，确认每个模块都有对应文件

2. **生成索引文件 `WORK_DIR/requirements/index.md`**（Step 5 subagent 通过此文件快速定位需求）：

```markdown
# 需求文档索引

> 分拆模式索引：列出每个模块的需求文档路径和功能点，供 Step 5 subagent 按需读取。
> 所有 subagent 必须先读取本文件，再按模块名找到对应文件路径后读取。

## 共用文件

| 内容 | 文件路径 |
|------|---------|
| 产品概述 / 用户角色 / 核心流程 / 数据模型 / 枚举值字典 / 原型图清单 | requirements/详细需求文档_overview.md |

## 模块文件

| 模块名 | 文件路径 | 功能点数 | 页面数 |
|--------|---------|---------|-------|
| [用户模块] | requirements/详细需求文档_用户模块.md | [N] | [M] |
| [商品模块] | requirements/详细需求文档_商品模块.md | [N] | [M] |
| [订单模块] | requirements/详细需求文档_订单模块.md | [N] | [M] |
| ... | ... | ... | ... |

## 读取规则

- **读取某模块的需求**：先读 index.md 找到文件路径 → 再读对应模块文件
- **读取用户角色/枚举值**：读 requirements/详细需求文档_overview.md §2 / §5.5
- **读取原型图清单**：读 requirements/详细需求文档_overview.md §7
```

3. **更新执行状态：** 在 `WORK_DIR/执行状态.md` 中记录：

```markdown
## 需求文档模式

| 项目 | 内容 |
|------|------|
| 文档模式 | 分拆模式（模块数 N > 3） |
| Overview 文件 | requirements/详细需求文档_overview.md |
| 模块文件 | requirements/详细需求文档_用户模块.md, requirements/详细需求文档_商品模块.md, ... |
```

3. **输出汇总：**

```
✅ 需求文档生成完毕（分拆模式）
  📄 requirements/详细需求文档_overview.md（产品概述/用户角色/流程/数据模型/清单）
  📄 requirements/详细需求文档_用户模块.md（N 个功能点）
  📄 requirements/详细需求文档_商品模块.md（M 个功能点）
  ...
共 [X] 个模块文件，Step 5 各 subagent 将按模块独立加载对应文件。
```

> **不执行合并操作。** 分拆模式下永远不生成合并版 `requirements/详细需求文档.md`，以保持上下文精简。
