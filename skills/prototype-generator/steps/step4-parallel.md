# 大型需求文档并行分块编写流程

> **触发条件：** 命中默认强制压缩模式时加载本文件；常见触发信号包括模块数 > 3、功能点数 > 12、预估页面 / swimlane 数 > 8、终端数 > 1、关键角色数 > 3、原始资料总内容 > 3000 行。
>
> **核心变化：** 大型项目需求文档**不再合并为单一大文件**，而是拆分为 1 个共用 overview 文件 + N 个模块文件 + N 个模块摘要文件，永久保留。这样 Step 5 / Step 6 每个 subagent 先读 `overview + module_brief`，只在必要时再读模块详细文档，上下文显著缩减。
>
> **200K 预算补充：** 面向 `Codex 5.4 Medium / 200K` 时，本文件不是“超大项目专用优化”，而是默认主路径。目标不是让单个子任务读完所有需求，而是让每个子任务只持有完成当前模块所需的最小上下文。

---

## 文件结构约定

```
WORK_DIR/
└── requirements/
    ├── 详细需求文档_overview.md        ← 共用部分（角色、系统边界、导航、流程、数据模型、原型图清单）
    ├── module_briefs/
    │   ├── 模块摘要_[模块中文名].md    ← 每个模块一页摘要，供 Step 5 / Step 6 优先读取
    │   └── ...
    ├── 详细需求文档_[模块中文名].md    ← 每个模块一个文件，只含该模块的功能点+增强 PRD 区块
    ├── 详细需求文档_[模块中文名].md
    ├── index.md
    └── ...
```

> **注意：** 不生成合并版 `详细需求文档.md`。所有后续步骤（Step 5、Step 6）通过读取 `index.md + overview + module_brief + 对应模块文件` 获取完整信息。
> **自动重写规则：** 若后续阶段发现 `overview/module_briefs/index` 缺失、过旧或覆盖不足，可由主控器自动重写这些压缩产物；重写目标是恢复“最小可执行上下文”，不是回退到单文件大 PRD。

## 步骤一：生成共用 overview 文件

主进程直接生成 `WORK_DIR/requirements/详细需求文档_overview.md`，包含以下章节（**不含**功能模块清单 §3）：

```markdown
# [产品名称] 详细需求文档 — Overview

## 1. 产品概述
## 2. 用户角色
## 2.5 系统边界与外部依赖
## 2.8 模块职责与协作关系
## 3.5 移动端导航结构（有移动端 App/小程序时必填）
## 3.6 后台导航结构（有后台 Web/Admin 时必填）
## 4. 核心业务流程
## 4.5 关键业务事件
## 5. 数据模型与状态
## 5.5 枚举值字典
## 5.8 权限与数据口径总则
## 6. 非功能需求
## 7. 原型图清单
```

> **§3.5 移动端导航结构** 必须在 overview 中，因为所有模块的移动端 subagent 都需要知道哪些页面有底部 Tab Bar。
> **§3.6 后台导航结构** 必须在 overview 中，因为所有后台页面都依赖左侧菜单树和导航归属。
> **§7 原型图清单** 必须在 overview 中，包含所有模块的页面，至少给出页面类型、页面原型类型、导航归属、是否主导航页、主要字段数量和业务规则展示重点。
> **§5.5 枚举值字典** 必须在 overview 中，跨模块共用的状态枚举值集中在此定义。
> **§2.5 / §2.8 / §4.5 / §5.8** 是增强 PRD 的全局输入，Step 5 和后续 skill 都会依赖这些章节理解系统边界、模块关系、关键事件和权限口径。

## 步骤二：并行生成各模块文件与模块摘要

将所有模块分配给并行子任务，每个子任务负责 1-2 个模块（Codex 建议每个子任务 1 个模块），并且**任一时刻最多只运行 3 个子 agent**，超出部分分批执行。

每个模块独立输出为 `WORK_DIR/requirements/详细需求文档_[模块中文名].md`，只含该模块的 §3 内容：

```markdown
# [产品名称] — [模块名]需求

## 3. 功能模块清单 — [模块名]

### [模块名]

#### 功能点 X.1：[功能名称]
...（完整字段规格、开发关注点、权限与可见范围、数据影响、三态设计、验收标准）
```

**子任务提示词模板：**

```
编写以下模块的需求文档，保存为 [WORK_DIR绝对路径]/requirements/详细需求文档_[模块中文名].md。

【写作范围】只写该模块的"## 3. 功能模块清单"内容，包含完整字段规格：
- [模块名]：[功能点列表]

【参考资料】
- 读取 [WORK_DIR绝对路径]/requirements/详细需求文档_overview.md 第2章"用户角色"、第2.5章"系统边界与外部依赖"、第2.8章"模块职责与协作关系"
- 有移动端时读取第3.5章"移动端导航结构"；有后台时读取第3.6章"后台导航结构"
- 读取第4.5章"关键业务事件"、第5.5章"枚举值字典"、第5.8章"权限与数据口径总则"
- 读取 [WORK_DIR绝对路径]/.prototype-generator/竞品分析报告.md 中 [模块名] 相关章节（获取竞品洞察）

【格式】严格遵循 step4-doc-format.md 中功能模块清单的结构，每个功能点必须包含：
- 开发关注点
- 权限与可见范围
- 数据影响
- 字段规格区块（▌列表/查询页字段规格 / ▌新增/编辑表单字段规格 / ▌详情/状态页字段规格）
- 三态设计表格（▌三态设计）
- 可见角色字段

【自查规则】每写完一个功能点，检查是否有开发关注点、权限与可见范围、数据影响、对应字段规格区块和三态设计；缺少则立即补全后再继续下一功能点。

完成后输出：✅ requirements/详细需求文档_[模块中文名].md 完成，N 个功能点，M 行。
```

每个模块完成详细文档后，主进程或同一子任务必须继续生成：

- `WORK_DIR/requirements/module_briefs/模块摘要_[模块中文名].md`

模块摘要固定控制在一页内，供后续 agent 优先读取，必须包含：

```markdown
# [模块名] 模块摘要

## 1. 模块目标与边界
## 2. 终端与导航归属
## 3. 页面清单与页面 archetype
## 4. 核心实体与 CRUD 闭环
## 5. 关键字段索引
## 6. 状态 / 枚举摘要
## 7. 权限与数据口径摘要
## 8. 跨模块跳转与外部依赖
## 9. 详细文档章节映射
```

模块摘要要求：
- 只保留本模块最小可执行上下文，优先使用表格、清单、映射，避免长段落
- 必须明确页面数、关键字段、关键状态、核心按钮、CRUD 缺一不可项
- 必须给出“需要回读详细文档的场景”，例如复杂校验规则、状态流转、外部依赖失败处理
- Step 5 / Step 6 子 agent 默认先读模块摘要，再按需定位模块详细文档
- 目标是让单个 `module_brief` 保持在“一次可快速读完”的尺度，默认不超过一页；若超出一页，继续压缩为字段索引、状态索引和跳转索引，优先删长段解释

**Claude Code（Agent 工具）— 分批并行启动，每批最多 3 个 Agent：**

```
# 每批最多 3 个，先并行发出本批，再等待本批完成
Agent(prompt="...模块1 完整 prompt（所有占位符已替换）...", run_in_background=True)
Agent(prompt="...模块2 完整 prompt（所有占位符已替换）...", run_in_background=True)
Agent(prompt="...模块3 完整 prompt（所有占位符已替换）...", run_in_background=True)
# 若还有剩余模块，下一批重复相同步骤
```

> Claude Code 请参考 `SKILL_DIR/steps/claude-rules.md`；Codex 请参考 `SKILL_DIR/steps/codex-rules.md`。

**Codex：**

```
# 用 spawn_agent 按模块分批启动，每批最多 3 个，wait 当前批完成后再启动下一批
spawn_agent(agent_type="worker", message="...模块1 完整 prompt（所有占位符已替换）...")
spawn_agent(agent_type="worker", message="...模块2 完整 prompt（所有占位符已替换）...")
spawn_agent(agent_type="worker", message="...模块3 完整 prompt（所有占位符已替换）...")
```

## 步骤三：验收与生成索引文件

所有模块文件生成后：

1. **完整性验收：** 用当前会话可用的文件列表命令列出 `WORK_DIR/requirements/详细需求文档_*.md` 与 `WORK_DIR/requirements/module_briefs/模块摘要_*.md`，确认每个模块都有对应详细文档和模块摘要

2. **生成索引文件 `WORK_DIR/requirements/index.md`**（Step 5 subagent 通过此文件快速定位需求）：

```markdown
# 需求文档索引

> 分拆模式索引：列出每个模块的需求文档路径、模块摘要路径和功能点，供 Step 5 / Step 6 subagent 按需读取。
> 所有 subagent 必须先读取本文件，再按模块名找到 `module_brief` 和模块详细文档路径后读取。

## 共用文件

| 内容 | 文件路径 |
|------|---------|
| 产品概述 / 用户角色 / 系统边界 / 模块职责 / 导航结构 / 核心流程 / 关键业务事件 / 数据模型 / 枚举值字典 / 权限口径 / 原型图清单 | requirements/详细需求文档_overview.md |

## 模块文件

| 模块名 | 详细文档路径 | 模块摘要路径 | 功能点数 | 页面数 | 核心实体 | 外部依赖 |
|--------|--------------|--------------|---------|-------|---------|---------|
| [用户模块] | requirements/详细需求文档_用户模块.md | requirements/module_briefs/模块摘要_用户模块.md | [N] | [M] | [用户/角色/组织] | [短信/认证] |
| [商品模块] | requirements/详细需求文档_商品模块.md | requirements/module_briefs/模块摘要_商品模块.md | [N] | [M] | [商品/分类/SKU] | [ERP/图片存储] |
| [订单模块] | requirements/详细需求文档_订单模块.md | requirements/module_briefs/模块摘要_订单模块.md | [N] | [M] | [订单/发货单/退款单] | [支付/物流/消息] |
| ... | ... | ... | ... | ... | ... |

## 读取规则

- **读取某模块的需求**：先读 index.md 找到模块摘要路径和详细文档路径 → 先读对应模块摘要 → 仅在需要字段明细、复杂校验、状态流转或失败处理时再读对应模块文件
- **读取用户角色/枚举值**：读 requirements/详细需求文档_overview.md §2 / §5.5
- **读取系统边界/导航/权限规则**：读 requirements/详细需求文档_overview.md §2.5 / §2.8 / §3.5 / §3.6 / §4.5 / §5.8
- **读取原型图清单**：读 requirements/详细需求文档_overview.md §7
- **Step 5 / Step 6 默认读取顺序**：`index.md -> overview -> module_brief -> 模块详细文档 -> page_spec`
- **200K 预算限制**：单个 Step 5 / Step 6 子任务默认只允许读取 `1 个模块摘要 + 1 个模块详细文档`；若需要第二个模块的细节，必须先把跨模块依赖压缩回 overview 或模块摘要，再发起下一轮任务
```

3. **更新执行状态：** 在 `WORK_DIR/.prototype-generator/执行状态.md` 中记录：

```markdown
## 需求文档模式

| 项目 | 内容 |
|------|------|
| 文档模式 | 分拆模式（模块数 N > 3） |
| Overview 文件 | requirements/详细需求文档_overview.md |
| 模块摘要目录 | requirements/module_briefs/ |
| 模块文件 | requirements/详细需求文档_用户模块.md, requirements/详细需求文档_商品模块.md, ... |
```

3. **输出汇总：**

```
✅ 需求文档生成完毕（分拆模式）
  📄 requirements/详细需求文档_overview.md（角色/系统边界/导航/流程/事件/数据模型/清单）
  📄 requirements/module_briefs/模块摘要_用户模块.md（摘要优先读取）
  📄 requirements/详细需求文档_用户模块.md（N 个功能点）
  📄 requirements/详细需求文档_商品模块.md（M 个功能点）
  ...
共 [X] 个模块文件 + [X] 个模块摘要文件，Step 5 / Step 6 各 subagent 将按 `index -> overview -> module_brief -> detail` 顺序独立加载。
```

> **不执行合并操作。** 分拆模式下永远不生成合并版 `requirements/详细需求文档.md`，以保持上下文精简。
