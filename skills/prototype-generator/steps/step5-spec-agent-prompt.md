# 规格化 Agent 提示词模板（draw.io 两阶段架构 — 阶段 A）

> 本文件仅用于 draw.io 模式的两阶段生成流程。
> HTML 模式仍使用 `step5-agent-prompt.md` 中的 HTML 模板。

---

## 职责说明

规格化 Agent 负责 **业务决策**：读取需求文档 → 确定每个页面的 UI 元素 → 计算每个元素的坐标 → 输出结构化的 `page_spec_[模块英文名].md` 文件。

渲染 Agent 不做任何业务判断，只做 **格式转换**：读取 page_spec → 查找样式字典 → 生成 draw.io XML。

---

## ⚠️ 强制输出格式声明

**本 Agent 的唯一输出是符合 page_spec 表格格式的 .md 文件。**

**禁止输出描述性文字**（如 `- 轮播区：3张轮播占位`、`- 顶部：标题"渔易购"，右侧消息图标`）。

**必须是 Markdown 表格**，每行一个 UI 元素，包含以下列：
- `id` | `parent_swimlane` | `component_type` | `value` | `x` | `y` | `width` | `height` | `style_key` | `tooltip`

**错误示例（禁止）：**
```markdown
## 页面 1：App-首页
- 画布：390x844，移动端线框图
- 顶部：标题"渔易购"，右侧消息图标
```

**正确示例（必须）：**
```markdown
## 元素列表
| id | parent_swimlane | component_type | value | x | y | width | height | style_key | tooltip |
| 2  | S1             | nav            | 渔易购 | 0 | 38 | 375 | 56 | nav | |
| 3  | S1             | text           | 消息  | 320 | 50 | 40 | 32 | icon | |
```

### 3.0 Tab 页拆分（进入3.1前必须执行）

检查本模块每个页面：若需求文档描述该页面含有多个 Tab 切换内容（如"系统管理"含部门/角色/权限/管理员/基础设置），**必须将每个 Tab 拆分为独立 swimlane**，不得在单一 swimlane 内绘制 Tab 栏 + 混合内容：

### 3.3 在模板标记处填入业务字段

在模板中 `{{业务字段区}}` 标记处，根据第二步提取的字段列表逐行插入：

**列表页 — 表格列标题区和数据行区：**
- 按需求文档的列名逐列添加 table_header 行，x 坐标按列宽顺序排开
- 然后添加 3 行数据行（table_row_odd / table_row_even 交替），每行每列一个 cell
- 操作列每行添加 btn_sm（编辑）+ btn_sm_danger（删除）

**表单页 — 字段区：**
- 按需求文档的字段列表逐个添加 label + input 行

- 下拉选择用 select，多行文本用 textarea

**详情页 — 键值对区：**
- 按需求文档的展示字段逐个添加 label + text_value 行
- 每行放 2 组（左侧 x=48/176，右侧 x=480/608），y 递增 40

**id 分配：** 从模板最大固定 id 之后递增

## 第五步：自查

写入文件后，立即执行以下自查，发现问题用 Edit 修复：

**元素数量硬检查（不满足不得提交）：**

每个 swimlane 必须满足以下最低元素数量要求（用于确保 UI 临摹品质）：

| 页面类型 | 最小元素数 | 必须包含 |
|---------|----------|---------|
| 移动端列表页（含卡片流） | 25+ | 筛选区(5) + 3行数据卡片(每卡6元素=18) + 空状态(1) + 分页(3) + 标注(2) |
| 移动端列表页（含弹窗） | 35+ | 列表页(25) + 弹窗 swimlane(10) |
| 移动端表单页 | 20+ | 每个字段 2 行（label + input），5 字段 = 10，加导航/背景/按钮/标注 |
| Web 列表页 | 35+ | 筛选区(8) + 表头(8) + 3行数据(每行8列=24) + 操作(3) + 标注(2) |
| Web 表单页 | 25+ | 每个字段 2 行（label + input），8 字段 = 16，加导航/背景/按钮/标注 |
| 登录/注册页 | 10+ | 导航 + 背景 + 2-3 字段（每字段 2 行）+ 按钮 + 标注 |
| 弹窗 swimlane | 8+ | 弹窗背景 + 标题 + 2-3 字段 + 确认/取消按钮 |

**检查方法：**
统计每个 swimlane 的元素列表行数（`| id |` 前缀行），不足时继续展开：
- 列表页：补充更多数据行（不同状态）
- 表单页：回查需求文档，补齐遗漏字段
- 详情页：补充更多展示字段

**字段完整性自查：**
- 表单页：需求文档中每个字段是否都有对应的 label 行 + input 行？
- 列表页：表格是否有 ≥3 行数据行（id 各不同的 table_row 行）？
- 详情页：所有展示字段是否都有 label + value 两行？

**坐标合法性自查：**
- 所有 x, y, width, height 是否都是 8 的倍数？
- 标注元素 x + width 是否超出 swimlane 右边界？（移动端>595，Web>1700）
- 是否有 y < 38 的元素（会被 swimlane 标题栏遮挡）？

**内容真实性自查：**
- value 列是否有「字段一/字段二」「列表项1/数据项N」「示例数据」「真实字段」等占位词？
- 若有，替换为需求文档中的实际业务名称

**CRUD 完整性自查：**
- 包含增删改操作的列表页：是否在 page_spec 中包含了弹窗 swimlane 的行？
- 每个列表数据行：是否有 btn_sm（编辑）+ btn_sm_danger（删除）？

## UI 临摹品质要求

生成的原型将用于 UI 设计临摹参考，必须满足以下品质标准：

### 1. 数据行多样性
- 列表页必须包含 ≥3 行数据，每行状态不同（如：待支付/已发货/已完成）
- 必须包含空状态提示（如"暂无数据"）
- 数据值使用真实业务场景（不使用"数据1/数据2"等占位符）

### 2. 字段完整性
- 表单页必须包含需求文档该功能点的所有字段
- 每个字段必须逐一展开为 label + input 对（2 行）
- 不得遗漏任何字段

### 3. 枚举值体现
- 状态列、类型列等必须使用需求文档 §5.5 枚举值字典的真实值
- 下拉选择框的 tooltip 必须列出所有可选值（来自枚举字典）
- 不使用"选项1/选项2"等占位符

### 4. 必填标注
- 必填字段的 label 必须使用 `label_required` 样式
- 必填字段的 value 必须包含 `*` 标记（如"订单状态*"）

### 5. 操作按钮 tooltip
- 所有主操作按钮（新增/编辑/删除/提交/审核等）必须有 tooltip
- tooltip 必须说明跳转目标或操作结果（如"跳转订单详情页"、"提交后进入审核流程"）

### 6. 交互反馈
- 包含增删改操作的列表页必须有对应的弹窗 swimlane
- 弹窗必须包含完整的表单字段（不得简化）

### 7. 布局合理性
- 移动端：单列布局，字段垂直排列
- Web 端：可使用双列布局（左右各一列字段）
- 所有元素坐标必须符合 8px 栅格系统
