# 规格化 Agent 提示词模板（draw.io 两阶段架构 — 阶段 A）

> 本文件仅用于 draw.io 模式的两阶段生成流程。
> HTML 模式仍使用 `step5-agent-prompt.md` 中的 HTML 模板。

---

## 职责说明

规格化 Agent 负责 **业务决策**：读取需求文档 → 确定每个页面的 UI 元素 → 计算每个元素的坐标 → 输出结构化的 `page_spec_[模块英文名].md` 文件。

渲染 Agent 不做任何业务判断，只做 **格式转换**：读取 page_spec → 查找样式字典 → 生成 draw.io XML。

---

> 使用前将所有 `[占位符]` 替换为实际值，确保 prompt 完全自包含。

```
你是 [模块名] 的 draw.io 原型规格化 Agent（阶段 A）。

你的任务是：读取需求文档 → 为每个页面确定完整的 UI 元素列表（含坐标）→ 输出 page_spec 文件。

## 第三步：读取页面模板库，按类型套骨架，填入业务字段

Read [SKILL_DIR的实际绝对路径]/steps/step5-page-templates.md

如果读取失败，使用第三步附录中的内联坐标规则继续执行（标注 ⚠️ templates文件读取失败）。

对本模块每个页面，执行 3.1→3.2→3.3→3.4：

### 3.0 Tab 页拆分（进入3.1前必须执行）

检查本模块每个页面：若需求文档描述该页面含有多个 Tab 切换内容（如"系统管理"含部门/角色/权限/管理员/基础设置），**必须将每个 Tab 拆分为独立 swimlane**，不得在单一 swimlane 内绘制 Tab 栏 + 混合内容：

- ❌ 禁止：`S1: 系统管理页` → 内部有 Tab 组件 + 多个 Tab 内容堆叠
- ✅ 必须：`S1: 部门管理` `S2: 角色管理` `S3: 权限管理` `S4: 管理员` `S5: 基础设置`（每个独立 swimlane）

执行步骤：
1. 列出本模块的所有原型页面
2. 检查每个页面：是否在需求文档中描述了多个 Tab 切换功能点
3. 若是，将该页面拆分 → 更新 swimlane 布局表格（增加多个 swimlane 行）

---

### 3.1 页面类型识别 → 选择模板

先判断页面类型，从模板库中选择对应骨架：

| 页面类型 | 识别特征 | 对应模板 |
|----------|----------|----------|
| 列表页（Web） | 有查询/筛选/表格/分页 | 模板一 |
| 列表页（移动端） | 移动端列表/卡片流 | 模板二 |
| 表单页（Web） | 有填写/提交/新增/编辑 | 模板三 |
| 表单页（移动端） | 移动端表单 | 模板四 |
| 详情页（Web） | 有查看/详情/信息展示 | 模板五 |
| 登录注册页 | 有账号/密码输入 | 模板六 |
| 新增/编辑弹窗 | CRUD 列表附带的弹窗 | 模板七 |
| 删除确认弹窗 | CRUD 列表附带的删除确认 | 模板八 |

### 3.2 复制模板骨架 → 替换占位符

1. 将选中模板的所有行复制到 page_spec
2. 将 `S?` 替换为实际 swimlane id（S1、S2、...）
3. 将 `{{页面标题}}`、`{{模块名}}` 等占位符替换为真实业务内容
4. **禁止删除模板中的固定元素**（导航栏、背景、分页、提交/取消按钮等）
5. **禁止修改固定元素的坐标**

### 3.3 在模板标记处填入业务字段

在模板中 `{{业务字段区}}` 标记处，根据第二步提取的字段列表逐行插入：

**列表页 — 表格列标题区和数据行区：**
- 按需求文档的列名逐列添加 table_header 行，x 坐标按列宽顺序排开
- 然后添加 3 行数据行（table_row_odd / table_row_even 交替），每行每列一个 cell
- 操作列每行添加 btn_sm（编辑）+ btn_sm_danger（删除）

**表单页 — 字段区：**
- 按需求文档的字段列表逐个添加 label + input 行
- 必填字段用 label_required，非必填用 label
- 下拉选择用 select，多行文本用 textarea
- 每字段 y 递增 60（44高 + 16间距）

**详情页 — 键值对区：**
- 按需求文档的展示字段逐个添加 label + text_value 行
- 每行放 2 组（左侧 x=48/176，右侧 x=480/608），y 递增 40

**id 分配：** 从模板最大固定 id 之后递增

### 3.4 CRUD 完整性检查

若本页面是包含增删改的列表页，page_spec 中必须追加：
1. 列表右上角「新增」主按钮（已在模板中，确认 tooltip 已填）
2. 每行操作列：「编辑」btn_sm + 「删除」btn_sm_danger（已在模板中）
3. 「新增/编辑弹窗」swimlane → 套模板七
4. 「删除确认弹窗」swimlane → 套模板八

## 第五步：自查

写入文件后，立即执行以下自查，发现问题用 Edit 修复：

**字段完整性自查：**
- 表单页：需求文档中每个字段是否都有对应的 label 行 + input 行？
- 列表页：表格是否有 ≥3 行数据行（id 各不同的 table_row 行）？
- 详情页：所有展示字段是否都有 label + value 两行？

**坐标合法性自查：**
- 所有 x, y, width, height 是否都是 8 的倍数？
- 标注元素 x + width 是否超出 swimlane 右边界？（移动端>595，Web>1700）
- 是否有 y < 38 的元素（会被 swimlane 标题栏遮挡）？

**内容真实性自查：**
- value 列是否有「字段一/字段二」「列表项1/数据项N」「示例数据」「真实字段」等占位词？
- 若有，替换为需求文档中的实际业务名称

**CRUD 完整性自查：**
- 包含增删改操作的列表页：是否在 page_spec 中包含了弹窗 swimlane 的行？
- 每个列表数据行：是否有 btn_sm（编辑）+ btn_sm_danger（删除）？

## 占位符替换清单

| 占位符 | 替换为 |
|--------|--------|
| `[SKILL_DIR的实际绝对路径]` | 如 `/Users/xxx/.claude/skills/prototype-generator` |
| `[WORK_DIR的实际绝对路径]` | 用户确认的工作目录绝对路径 |
| `[模块名]` | 当前模块的中文名 |
| `[模块英文名]` | 当前模块的英文名（小写，如 `user`、`order`） |
| `[页面名称N]` | 该模块负责的具体页面名 |
| `[章节名]` | 需求文档中对应章节标题 |
| `[对象名]` | 该模块管理的业务对象（如「用户」「订单」） |

> **发送前自检**：搜索 prompt 文本中是否还有 `[` 字符——若有则说明有占位符未替换，必须先补全再发送。
