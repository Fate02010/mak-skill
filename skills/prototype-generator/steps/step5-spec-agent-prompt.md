# 规格化 Agent 提示词模板（draw.io 两阶段架构 — 阶段 A）

> 本文件仅用于 draw.io 模式的两阶段生成流程。
> HTML 模式仍使用 `step5-agent-prompt.md` 中的 HTML 模板。

---

## 职责说明

规格化 Agent 负责 **业务决策**：读取需求文档 → 确定每个页面的 UI 元素 → 计算每个元素的坐标 → 输出结构化的 `page_spec_[模块英文名].md` 文件。

渲染 Agent 不做任何业务判断，只做 **格式转换**：读取 page_spec → 查找样式字典 → 生成 draw.io XML。

---

## ⚠️ 强制输出格式声明

**本 Agent 的唯一输出是符合 page_spec 表格格式的 .md 文件。**

**禁止输出描述性文字**（如 `- 轮播区：3张轮播占位`、`- 顶部：标题"渔易购"，右侧消息图标`）。

**必须是 Markdown 表格**，每行一个 UI 元素，包含以下列：
- `id` | `parent_swimlane` | `component_type` | `value` | `x` | `y` | `width` | `height` | `style_key` | `tooltip`

**错误示例（禁止）：**
```markdown
## 页面 1：App-首页
- 画布：390x844，移动端线框图
- 顶部：标题"渔易购"，右侧消息图标
```

**正确示例（必须）：**
```markdown
## 元素列表
| id | parent_swimlane | component_type | value | x | y | width | height | style_key | tooltip |
| 2  | S1             | nav            | 渔易购 | 0 | 38 | 375 | 56 | nav | |
| 3  | S1             | text           | 消息  | 320 | 50 | 40 | 32 | icon | |
```

### 3.2 复制模板骨架 → 替换占位符

1. 将选中模板的所有行复制到 page_spec
2. 将 `S?` 替换为实际 swimlane id（S1、S2、...）
3. 将 `{{页面标题}}`、`{{模块名}}` 等占位符替换为真实业务内容
4. **禁止删除模板中的固定元素**（导航栏、背景、分页、提交/取消按钮等）
5. **禁止修改固定元素的坐标**

### 3.3 在模板标记处填入业务字段

在模板中 `{{业务字段区}}` 标记处，根据第二步提取的字段列表逐行插入：

**列表页 — 表格列标题区和数据行区：**
- 按需求文档的列名逐列添加 table_header 行，x 坐标按列宽顺序排开
- 然后添加 5 行数据行（table_row_odd / table_row_even 交替），每行每列一个 cell
- 每行展示不同的业务状态（如：待支付/已支付/已发货/已完成/已取消），状态值来自需求文档枚举值字典
- 操作列每行添加 btn_sm（编辑）+ btn_sm_danger（删除）

**表单页 — 字段区：**
- 按需求文档的字段列表逐个添加 label + input 行
- 必填字段用 label_required，非必填用 label
- 下拉选择用 select，多行文本用 textarea
- 每字段 y 递增 60（44高 + 16间距）

**详情页 — 键值对区：**
- 按需求文档的展示字段逐个添加 label + text_value 行
- 每行放 2 组（左侧 x=48/176，右侧 x=480/608），y 递增 40

**id 分配：** 从模板最大固定 id 之后递增

### 3.4 CRUD 弹窗 swimlane 强制生成（硬门控）

对第二步补充中标记为"是"的每个列表页，逐一确认以下 4 项全部存在（任一缺失即为不合格）：

| 检查项 | 验证方法 | 缺失时动作 |
|--------|---------|-----------|
| ① 列表页「新增」按钮 | 元素列表中有 btn_primary 且 value 含"新增" | 追加 btn_primary 行 |
| ② 每行操作列有「编辑」+「删除」 | 每行数据行后有 btn_sm + btn_sm_danger | 追加操作按钮行 |
| ③ 新增/编辑弹窗 swimlane | swimlane 布局表中有 type=modal 且 label 含"新增/编辑" | 立即生成整个模板七 swimlane |
| ④ 删除确认弹窗 swimlane | swimlane 布局表中有 type=modal 且 label 含"删除确认" | 立即生成整个模板八 swimlane |

⚠️ 弹窗 swimlane 的字段必须来自需求文档（不得用占位符），字段数量 = 需求文档中该对象的新增/编辑字段数。

### 3.5 后台权限管理类页面特殊规则

当模块包含角色管理/资源管理/用户管理/权限分配等权限类功能时：

**角色管理列表页：** 表格列至少含：角色名称、角色编码、角色描述、创建时间、状态、操作。新增/编辑弹窗字段含：角色名称（必填）、角色编码（必填）、角色描述、备注。
**资源管理列表页（菜单/权限）：** 表格列至少含：资源名称、资源类型（菜单/按钮/API）、路径/权限标识、排序号、状态。新增/编辑弹窗含：上级资源（select）、资源名称、资源类型（select）、路径、排序号。
**用户管理列表页：** 表格列至少含：用户名、姓名、手机号、角色、部门、状态、最后登录时间。新增/编辑弹窗含：用户名（必填）、密码、姓名、手机号、邮箱、部门（select）。
**用户绑定角色：** 用户管理列表页操作列增加「分配角色」btn_sm，点击弹出角色分配弹窗（Modal swimlane），弹窗内用 checkbox 列表展示所有角色（已绑定的打勾），底部确认/取消按钮。

### 3.6 swimlane 高度动态计算

所有元素填写完毕后，计算每个 swimlane 的实际所需高度：

```
swimlane_height = max(最后一个元素的 y + height + 16, 最低高度)
```

最低高度规则：
- 移动端 swimlane（含 bottom_bar）：860
- 移动端 swimlane（无 bottom_bar）：按内容计算，最小 600
- Web swimlane：960
- Modal swimlane：按内容计算，最小 280

将计算结果更新到 swimlane 布局表的 height 列。

## UI 临摹品质要求

生成的原型将用于 UI 设计临摹参考，必须满足以下品质标准：

### 1. 数据行多样性
- 列表页必须包含 ≥3 行数据，每行状态不同（如：待支付/已发货/已完成）
- 必须包含空状态提示（如"暂无数据"）
- 数据值使用真实业务场景（不使用"数据1/数据2"等占位符）

### 2. 字段完整性
- 表单页必须包含需求文档该功能点的所有字段
- 每个字段必须逐一展开为 label + input 对（2 行）
- 不得遗漏任何字段

### 3. 枚举值体现
- 状态列、类型列等必须使用需求文档 §5.5 枚举值字典的真实值
- 下拉选择框的 tooltip 必须列出所有可选值（来自枚举字典）
- 不使用"选项1/选项2"等占位符

### 4. 必填标注
- 必填字段的 label 必须使用 `label_required` 样式
- 必填字段的 value 必须包含 `*` 标记（如"订单状态*"）

### 5. 操作按钮 tooltip
- 所有主操作按钮（新增/编辑/删除/提交/审核等）必须有 tooltip
- tooltip 必须说明跳转目标或操作结果（如"跳转订单详情页"、"提交后进入审核流程"）

### 6. 交互反馈
- 包含增删改操作的列表页必须有对应的弹窗 swimlane
- 弹窗必须包含完整的表单字段（不得简化）

### 7. 布局合理性
- 移动端：单列布局，字段垂直排列
- Web 端：可使用双列布局（左右各一列字段）
- 所有元素坐标必须符合 8px 栅格系统
