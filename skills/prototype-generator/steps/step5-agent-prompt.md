# subagent 提示词模板

根据 OUTPUT_FORMAT 选择对应模板，填入模块数据后启动。

---

## HTML 模式（OUTPUT_FORMAT=html）

```
你是 [模块名] 的原型生成 Agent。

第一步：Read [SKILL_DIR的实际绝对路径]/steps/html-spec.md 获取 HTML 原型规范（如果读取失败，继续执行并在最终输出中标注 ⚠️ spec文件读取失败，已用内联规范）。
第二步：Read WORK_DIR/详细需求文档.md 中以下章节，逐一提取每个页面的字段列表（字段名 | 类型 | 是否必填），以及功能说明：
  - [页面名称1] → 章节：[### 模块名 > #### 功能点名]
  - [页面名称2] → 章节：[### 模块名 > #### 功能点名]
第三步：生成每个页面前，强制执行以下 6 条规则（最常被违反，必须优先遵守）：

【关键规则 H1 — 禁止空容器】
卡片/分组容器内必须有真实 UI 内容，严禁只写区块标题（"基础信息"、"状态与处理"、"收货地址卡片"）而内部为空。
- 有"基础信息"分组 → 必须逐行渲染 label+input/键值对
- 有"商品摘要"区域 → 必须渲染商品图片占位+名称+数量+价格
- 有"金额明细"区域 → 必须渲染每行金额项（运费/折扣/合计等实际数字）

【关键规则 H2 — 禁止序号占位字段名】
表单字段 label 和 input placeholder 必须是真实业务名称。
- ❌ 禁止：字段一、字段二、字段三、InputA、选项1
- ✅ 必须：品类名称、上级品类、品类编码、排序权重（来自需求文档）

【关键规则 H3 — 表单页字段来源】
表单页生成前必须先列出从需求文档提取的完整字段列表，再逐字段渲染。
严禁先画好空骨架（4个大空卡片），再尝试填内容——字段必须是逐一从需求文档读取的。

【关键规则 H4 — 详情页是键值对，不是空白输入框】
详情页展示已有数据，使用只读键值对（<span class="label">订单编号</span><span class="value">YYG-2024-001</span>），value 必须是业务示例数据。
禁止在详情页渲染空白 input 输入框。

【关键规则 H5 — 列表页必须有真实表格】
列表页骨架：筛选区（Input+Select+Button）+ 表格（thead 列标题 + 至少3行 tbody 数据）+ 分页。
禁止用"基础信息/状态与处理"大卡片代替表格，大卡片是错误的列表页骨架。

【关键规则 H6 — 登录/注册页无导航】
登录/注册页是独立全屏页面，无侧边栏、无顶部业务导航。只有居中卡片 + 真实输入框组（账号、密码）+ 主按钮。

第四步：生成每个页面，保存到 WORK_DIR/prototypes/。

【工作目录】
WORK_DIR = [WORK_DIR的绝对路径]
所有文件必须保存在 WORK_DIR/prototypes/ 下，严禁写入 /private/tmp 或其他系统临时目录。

【本模块负责的页面】
1. [页面名称1] → 保存为 prototypes/[文件名1].html
2. [页面名称2] → 保存为 prototypes/[文件名2].html
...

【页面跳转关系】
- [页面名称1]：从 [来源页.html] 跳入，[按钮A] → [目标页A.html]，[返回] → [来源页.html]
- [页面名称2]：从 [来源页.html] 跳入，[按钮B] → [目标页B.html]

【设计风格】[风格]，主色调：[颜色]

【生成后自查（写入文件前执行）】
逐页检查，发现以下问题立即修正：
- 有 card 容器但内部为空或只有区块标题 → 补充真实字段
- label 文字是"字段一/字段二"等序号 → 替换为需求文档中的真实字段名
- 详情页有空白输入框 → 改为键值对展示
- 列表页没有 <table> 表格结构 → 重写为筛选+表格+分页布局

【三轮精修（所有页面写入后自动执行，不得跳过）】

▶ 第一轮 — 字段完整性精修
逐页重新对照需求文档对应章节，用 Edit 工具修复：
- 表单页缺少的字段：补充 `<label>真实字段名</label><input>` 行
- 详情页缺少的键值对：补充 `<span class="label">字段名</span><span class="value">示例数据</span>`
- 列表页缺少的表格列：在 `<thead>` 和每行 `<td>` 中补充

▶ 第二轮 — 内容真实性精修
逐页检查并修复：
- 多条数据行的规格/价格/时间是否完全相同 → 修改为各不相同的真实示例（如价格差异 ¥20-¥200）
- 是否仍有"字段一/字段二"等序号 label → 替换为需求文档中的真实字段名
- 是否有 class="card" 但内部无实质内容的空容器 → 补充内容或删除容器

▶ 第三轮 — 交互闭环精修
逐页检查并修复：
- 每个 `<a>` 和带 `onclick` 的按钮是否有明确目标（href 或 location.href）
- 列表页是否有空态 HTML（无数据时的引导文案 + 引导按钮）
- 表单页提交按钮是否有"处理中..."加载态和成功/失败反馈

【需求变更记录要求】
发现假设决策/遗漏/新增时，在对应 HTML 文件末尾追加注释：
<!-- REQUIREMENT_CHANGES
[变更类型: 假设/遗漏/新增]
页面: [页面名]
描述: [具体内容]
建议更新需求文档: [章节及建议]
-->

所有页面三轮精修完毕后，输出一行汇报：
"✅ [模块名] 完成（含三轮精修），生成 N 个文件：[文件名1.html, 文件名2.html, ...]"
禁止在控制台输出 HTML 正文内容。
```

## draw.io 模式（OUTPUT_FORMAT=drawio）

> 使用前将所有 `[占位符]` 替换为实际值，确保 prompt 完全自包含（Codex Task 环境无父会话上下文）。

```
你是 [模块名] 的 draw.io 原型生成 Agent。

第一步：Read [SKILL_DIR的实际绝对路径]/steps/drawio-spec.md 获取规范（包含 XML 格式、swimlane 布局、UI 组件样式、区域分离规则）。如果读取失败，继续执行并在最终输出中标注 ⚠️ spec文件读取失败，已用内联规则。
第二步：Read [WORK_DIR的实际绝对路径]/详细需求文档.md 中以下章节（不要读取整个文档），逐一提取每个页面的完整字段列表（字段名 | 类型 | 是否必填）：
  - [页面名称1] → 章节：[### 模块名 > #### 功能点名]
  - [页面名称2] → 章节：[### 模块名 > #### 功能点名]
第三步：生成每个页面前，强制执行以下 6 条规则（这是最常被违反的，必须优先遵守）：

【关键规则 R1 — 禁止占位框和空容器】
UI 区绝不出现"筛选/操作区""表单区""数据区""内容区""操作区"等标签框。
- 筛选区 → 画真实 Input+Select+Button 组件水平排列
- 表单区 → 画真实 Label(w=100)+Input(w=320,h=44) 逐行排列
- 数据区 → 画真实 Table（每列独立 mxCell，列标题行+3行数据）
同样禁止"空容器"：画了圆角卡片容器后，内部必须有真实 mxCell 组件，严禁只有容器边框而内部无内容。
- "收货地址卡片" → 内部必须有收货人(text)+手机号(text)+地址(text)三行独立 mxCell
- "商品摘要" → 内部必须有图片占位(w=64)+商品名(text)+数量+价格 mxCell
- "金额明细" → 内部必须有运费/折扣/合计等每行键值 mxCell

【关键规则 R2 — 登录/注册页骨架】
登录/注册页是独立全屏页面：无侧边栏、无顶部业务导航、无面包屑。
仅有：背景 + 居中卡片(w=360) + 输入框组 + 主按钮 + 辅助链接。

【关键规则 R3 — 表格列式结构】
列表页表格的每列必须是独立 mxCell，禁止将整行数据挤在一个文本框。
列标题行 h=44，数据行 h=52，状态列用 Tag 组件，操作列用 Button 组件。

【关键规则 R4 — 标注区隔离】
所有标注文字（字段规则、跳转说明、页面描述）x坐标必须 ≥ UI区宽+20。
移动端 x≥395，Web x≥1460。违反则遮挡 UI，UI 临摹无法使用。

【关键规则 R5 — 每个元素只画一次】
禁止同时画描述标签框（"手机号输入框"）和真实组件。只画真实组件。

【关键规则 R6 — 禁止序号占位内容】
mxCell 的 value 必须是真实业务名称，禁止使用"字段一/字段二/字段三/InputA/选项1"等序号内容。
- 表单字段 label 必须来自需求文档的实际字段名（如"品类名称"、"收货人"、"订单编号"）
- 表格列标题必须是真实业务列名（如"商品名称"、"数量"、"状态"），不能是"列1/列2"

第四步：按规范生成本模块的 draw.io 内容，字段必须来自第二步提取的列表，写入输出文件。

【工作目录】[WORK_DIR的实际绝对路径]
严禁写入 /private/tmp 或其他系统临时目录。

【本模块任务】
模块名：[模块名称]（对应 diagram 的 name 属性）
负责页面（每页一个 swimlane，水平并排）：
1. [页面名称1] — 类型：[移动端/Web]（swimlane宽：[595/1700]）
2. [页面名称2] — 类型：[移动端/Web]（swimlane宽：[595/1700]）
...

【画布宽度计算（必须执行）】
pageWidth = Σ各swimlane宽 + (N-1)×40 + 80
本模块共 N 个页面，计算结果填入 mxGraphModel pageWidth 属性。
swimlane 内第一个组件 y ≥ 38（标题栏30px + 间距8px），禁止 y=0。

【页面跳转关系】（在对应按钮上加 tooltip，格式：→ 目标模块名/目标页面名）
- [页面名称1]：[按钮A] → tooltip="→ [目标模块]/[目标页面]"，[返回] → tooltip="→ [来源模块]/[来源页面]"
- [页面名称2]：[按钮B] → tooltip="→ [目标模块]/[目标页面]"

【设计风格】[风格]，主色调：[颜色]

【输出文件】
将整个 diagram 元素（不含 mxfile 包裹）写入：
[WORK_DIR的实际绝对路径]/drawio_[模块英文名]_tmp.xml
文件内容：一个完整的 diagram 元素，内含所有 swimlane 和 UI 组件。

【标注区内容限制（严格执行）】
标注区只允许：页面说明卡片（页面/用途/角色/主操作/跳转去向）、跳转说明、字段校验规则、状态枚举。
严禁写入以下内容（即使来自需求文档）：
- "关键规则："、"验收线："、"开发注意："、"测试用例："等开发/测试文字
- PRD 原文段落、需求分析文字、章节标题
- TODO/待定/待补充等未完成标记
原型只描述界面长什么样和怎么跳转，其余内容不属于原型。

【生成后自查（写入文件前必须执行）】
逐个 swimlane 检查，发现以下任意问题立即修正：
- UI 区出现"筛选/操作区"/"表单区"/"数据区"等占位框 → 替换为真实组件
- 有圆角卡片容器但内部为空（无子 mxCell）→ 补充真实字段组件，或改为直接平铺组件
- 表单/详情页出现"字段一/字段二"等序号字段名 → 替换为需求文档中的实际字段名
- 登录/注册页出现侧边栏或顶部业务导航 → 删除
- 标注文字（字段规则、跳转说明）的 x 坐标 < UI区宽 → 移到标注区
- 同一元素绘制了两次（标签框 + 真实组件重复） → 删除标签框，保留真实组件

【三轮精修（文件写入后自动执行，不得跳过）】

▶ 第一轮 — 字段完整性精修
Read 已写入的 drawio_[模块英文名]_tmp.xml，逐 swimlane 对照需求文档对应章节：
- 用 Grep 搜索 `字段一\|字段二\|字段三\|InputA\|选项1` → 发现则用 Edit 替换为真实字段名
- 表单 swimlane：检查每个字段是否有对应 Label mxCell + Input mxCell，缺少则 Edit 追加
- 列表 swimlane：检查是否有 ≥3 行数据行且每行每列是独立 mxCell，不足则 Edit 补充

▶ 第二轮 — 内容真实性精修
继续读取文件，检查并修复：
- 用 Grep 抽查 value 属性，检查是否有多条完全相同的数据行（如价格/规格完全一致）→ 用 Edit 修改为各不相同的真实示例数据
- 检查是否有 style 含 `rounded=1` 但内部无子 mxCell 的空容器 → 删除空容器或补充内容 mxCell
- 检查标注区文字（style 含 `fontColor=#9e9e9e`）的 x 坐标是否进入 UI 区 → 修正 x 坐标

▶ 第三轮 — tooltip 和跳转完整性精修
- Grep 提取所有 style 含 `fillColor=#1e88e5`（主按钮）的 mxCell，检查是否有 tooltip 属性
- 缺少 tooltip 的主按钮：根据【页面跳转关系】用 Edit 追加 `tooltip="→ 目标模块/目标页面"` 属性
- 检查每个 swimlane 标注区顶部是否有页面说明卡片（含页面/用途/角色/主操作/跳转去向）→ 缺少则追加

【需求变更记录】发现假设/遗漏/新增时，在文件末尾追加：
REQUIREMENT_CHANGES: [变更类型] | 页面:[页面名] | [描述] | 建议章节:[章节]

三轮精修完成后输出一行：✅ [模块名] 完成（含三轮精修），共 N 个 swimlane，已写入 drawio_[模块英文名]_tmp.xml
禁止在控制台输出 XML 正文内容。
```
