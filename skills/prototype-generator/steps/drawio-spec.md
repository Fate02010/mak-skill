# draw.io 原型规范（核心）

Spec Agent 加载本文件。样式字典在 `step5-component-styles.md`（由 render.py 脚本读取）。

生成的每个 `.drawio` 文件必须是**可直接在 draw.io / Diagrams.net 中打开**的合法 XML 文件。

---

## 最高优先级规则（读完本文件后，这6条必须始终在脑中）

> 以下规则是最常被违反、影响最大的，生成每个页面前必须逐条自检。

**1. 禁止区块占位框** — UI 区绝不能出现"筛选/操作区"/"表单区"/"数据区"等标签框。必须画真实组件：筛选区 = Input+Select+Button；表单区 = Label+Input 逐行；数据区 = Table 列式结构。

**2. 登录/注册页无任何导航** — 登录页是独立全屏页面，无侧边栏、无顶部业务导航、无面包屑。只有居中卡片+输入框+按钮。后台系统的登录页同样如此。

**3. 表格必须列式独立 mxCell** — 列表页的表格中，每列数据是独立的 mxCell，列标题行和数据行按列对齐。禁止将整行数据挤在一个 mxCell 里（如"记录1|编号XX|状态YY"）。

**4. 标注说明不得进入 UI 区** — 字段规则、跳转说明等所有标注文字，x 坐标必须 ≥ 标注区起点（移动端x≥400，Web x≥1464）。

**5. 每个元素只画一次** — 禁止同时画标签框（"手机号输入框"）和真实组件（实际 Input）。只画真实组件，不画描述性标签框。

**6. Sheet（diagram）必须按业务功能模块命名** — 每个 sheet 对应一个业务域（用户模块、商品模块、订单模块），**严禁以系统层命名**：

| 正确 | 禁止 |
|--------|--------|
| 用户模块 | APP系统 |
| 订单模块 | 后台管理 |
| 支付模块 | 移动端 |
| 营销模块 | Web端 |

> "APP系统"和"后台管理"不是功能模块，必须拆分为具体业务域。同一系统（如 App）的多个功能模块，应分别对应独立 sheet（用户模块一个 sheet、商品模块一个 sheet），而非合并为"APP系统"一个 sheet。

## 完整文件结构（必须严格遵守）

```xml
<mxfile host="app.diagrams.net" modified="2024-01-01T00:00:00.000Z" agent="Claude Code" version="24.0.0" type="device">
  <diagram id="[8位随机字母数字，如 aB3dEf7g]" name="[页面中文名]">
    <mxGraphModel dx="1034" dy="546" grid="0" gridSize="10" guides="1" tooltips="1" connect="1" arrows="1" fold="1" page="1" pageScale="1" pageWidth="[画布宽]" pageHeight="[画布高]" math="0" shadow="0">
      <root>
        <mxCell id="0" />
        <mxCell id="1" parent="0" />
        <!-- 所有 UI 元素从 id="2" 开始，必须有 parent="1" -->
      </root>
    </mxGraphModel>
  </diagram>
</mxfile>
```

**关键属性说明：**
- `mxfile` 必须包含 `host`、`modified`、`agent`、`version`、`type` 五个属性
- `diagram` 的 `id` 必须唯一，`name` 为页面显示名称
- `mxGraphModel` 必须包含 `dx`、`dy`、`grid`、`gridSize`、`guides`、`tooltips`、`connect`、`arrows`、`fold`、`page`、`pageScale`、`pageWidth`、`pageHeight`、`math`、`shadow` 全部属性
- `root` 下前两个 `mxCell`（id=0 和 id=1）是固定基础层，**不可省略**
- **parent 规则（按层级区分）：**
  - 直接放在画布上的元素（非 swimlane 内）：`parent="1"`
  - swimlane 容器本身：`parent="1"`
  - **swimlane 内的 UI 元素：`parent` = 该 swimlane 的 `id`，禁止写 `parent="1"`**
  - 如果没有使用 swimlane（单页面模式）：所有 UI 元素 `parent="1"`

**UI 区画布尺寸（页面实际设备宽度）：**
- 移动端：UI 区宽 `375`，高 `812`（iPhone 标准）
- 后台/Web：UI 区宽 `1440`，高 `900`

**swimlane 总宽度（含右侧标注区）：**
- 移动端 swimlane：宽 `595`（375 UI区 + 20 间隔 + 200 标注区），高 `860`
- Web swimlane：宽 `1700`（1440 UI区 + 20 间隔 + 240 标注区），高 `960`

> **标注区 x 起点**：移动端 x=400，Web x=1464（均为 8 倍数）

**混合系统画布尺寸规则（App + 后台同系统）：**
同一 diagram 内可以同时包含移动端页面和 Web 页面，每个 swimlane 根据其所属页面类型**独立选择宽度**：
- App/移动端页面 swimlane：宽 `595`，高 `860`
- 后台/Web 页面 swimlane：宽 `1700`，高 `960`
- 同一 diagram 中允许不同宽度的 swimlane 并排，只需确保 x 坐标正确累加（后一个 swimlane 的 x = 前一个 x + 前一个宽 + 40）

**swimlane 内组件 y 坐标起点规则：**
- swimlane 标题栏高度固定 `startSize=30`（标题占用 y:0~30）
- swimlane 内第一个组件 **y 坐标必须 ≥ 38**（30标题 + 8间距）
- 推荐：顶部导航栏 y=30，正文第一个组件 y=86（30+56导航高）
- **禁止**：组件 y=0，会被标题栏完全遮挡

## XML 特殊字符转义规则

| 原字符 | 转义写法 | 使用场景 |
|--------|----------|----------|
| `&` | `&amp;` | value 中出现 & 符号 |
| `<` | `&lt;` | value 中出现小于号 |
| `>` | `&gt;` | value 中出现大于号 |
| 换行 | `&#xa;` | value 中需要换行 |
| `"` | `&quot;` | value 中出现双引号 |

## 布局区与标注区严格分离（核心排版规则）

每个页面 swimlane 内部划分为两个水平区域，**二者绝不重叠**：

### UI 区规则（x: 0 ~ UI宽）

- **只放真实 UI 组件**：导航栏、输入框、按钮、表格、卡片、Tab、Tag、Modal、Pagination 等
- **坐标精确**：组件位置、尺寸必须符合间距规格，可直接作为高保真排版参考
- **禁止放入**：页面说明文字、业务规则说明、跳转注释、状态流程图、任何大文本框

### 标注区规则（x: UI宽+20 起）

**允许放入标注区的内容（仅限以下四类）：**
- **页面说明卡片**：页面名/用途/角色/主操作/跳转去向，置于标注区顶部
- **跳转说明**：列出所有按钮对应的跳转目标
- **字段规则**：字段校验规则（如"手机号格式"）、状态枚举值（如"待支付/已支付"）
- **状态流程图**：`待支付 → 已支付 → 已发货` 等流转关系（用小型流程图）

**严禁放入标注区（也严禁出现在 UI 区）的内容：**
- 开发规范/技术实现说明（如"关键规则："、"开发注意："）
- 验收标准/测试条件（如"验收线："、"测试用例："）
- TODO/FIXME/待定/待补充 等未完成标记
- 需求分析文字、章节标题、PRD 原文段落
- 任何以"规则："、"说明："、"注意："开头的大段文字块

> **原则**：原型只描述界面长什么样、怎么跳转。开发规范、验收标准属于其他文档，不属于原型。

所有标注元素样式：`text;html=1;strokeColor=none;fillColor=none;fontSize=10;fontColor=#9e9e9e;align=left;verticalAlign=top;`

**标注区禁止写入技术实现细节：**
- 禁止写像素尺寸规格（如"按钮高度 36"、"列表卡片 78"、"间距 16px"）
- 禁止写组件技术参数（如"font-size: 13"、"border-radius: 8"）
- 允许写业务规则（如"手机号格式：1[3-9]XXXXXXXXX"、"状态：待支付/已支付/已完成"）

### 快速检验

生成完成后，目视检查：左侧 UI 区截图是否可直接作为高保真设计稿参考图；右侧标注区是否完整包含所有说明文字。

## 形状（vertex）写法

所有形状必须包含 `vertex="1"` 和 `parent="1"`：

```xml
<mxCell id="[数字]" value="[显示文字]" style="[样式]" vertex="1" parent="1">
  <mxGeometry x="[X坐标]" y="[Y坐标]" width="[宽]" height="[高]" as="geometry" />
</mxCell>
```

> **`<mxGeometry>` 必须有 `as="geometry"` 属性，不可省略。**

## 连线（edge）写法（用于导航跳转地图 diagram）

```xml
<mxCell id="[数字]" value="[标注文字，可为空]" style="edgeStyle=orthogonalEdgeStyle;rounded=0;orthogonalLoop=1;jettySize=auto;exitX=1;exitY=0.5;exitDx=0;exitDy=0;entryX=0;entryY=0.5;entryDx=0;entryDy=0;" edge="1" source="[来源节点id]" target="[目标节点id]" parent="1">
  <mxGeometry relative="1" as="geometry" />
</mxCell>
```

> **连线必须包含 `edge="1"`、`source`、`target`、`parent="1"`，`<mxGeometry>` 必须有 `relative="1" as="geometry"`。**

## 页面跳转标注规范

draw.io 无法实现真实文件跳转，统一用以下两种方式标注：

1. **按钮/链接元素加 `tooltip` 属性**：`tooltip="→ 目标文件名.drawio"`
2. **页面底部跳转说明框**：用 `&#xa;` 换行，列出所有跳转关系

## 内容规范

- **真实数据**：使用符合业务场景的示例文字，严禁使用 `文字1`、`按钮A`、`示例内容`、`功能待定`、`待补充`、`数据N`、`Lorem ipsum` 等任何占位文字；字段 label 必须是真实业务名称（如"订单编号"而非"字段1"）
- **完整界面**：包含背景层、导航栏、主内容区、操作按钮、跳转说明框
- **id 连续递增**：从 2 开始，按从上到下、从左到右顺序，不可跳号或重复
- **XML 合法性**：value 中出现 `&`、`<`、`>` 必须转义；文件必须是合法闭合 XML

## 命名规范

### 文件命名

draw.io 模式**整个系统只输出一个文件**：`[产品名称].drawio`（如 `鲜渔到家.drawio`）。

**每个功能模块 = 一个 sheet（一个 `<diagram>`）**，模块内各页面用 swimlane 容器并排布局：

| 模块 | diagram name | 包含页面（swimlane） |
|------|-------------|---------------------|
| 用户模块 | `用户模块` | 登录页、注册页、个人中心 |
| 订单模块 | `订单模块` | 订单列表、订单详情、下单页 |
| 商品模块 | `商品模块` | 商品列表、商品详情 |
| 导航总览 | `导航-页面跳转地图` | 全系统页面跳转关系图 |

**subagent 输出约定：** 每个 subagent 负责一个模块，将该模块的**整个 `<diagram>`**（含所有页面 swimlane）写入临时文件 `WORK_DIR/drawio_[模块英文名]_tmp.xml`（仅含 `<diagram>` 元素，无 `<mxfile>` 包裹）。主流程等所有 subagent 完成后，将全部 `<diagram>` 合并写入 `WORK_DIR/prototypes/[产品名称].drawio`。

### 模块内页面布局（swimlane 并排）

同一 `<diagram>` 内，每个页面用 swimlane 容器包裹，水平并排排列：

- swimlane style：参照 `step5-component-styles.md` 中的 `swimlane` key
- 第一个 swimlane x=20，y=20；后续 x = 前一个 x + swimlane宽 + 40（间距）
- **移动端** swimlane 宽 595（375 UI区 + 20 + 200 标注区），高 860
- **Web** swimlane 宽 1700（1440 UI区 + 20 + 240 标注区），高 960
- swimlane 内元素 `parent` 指向 swimlane 的 `id`（不是 `"1"`）
- UI 组件 x: 0~UI宽；标注元素 x: 标注区起点起（移动端 x≥400，Web x≥1464）

### 页面/组件/连线命名规则

| 类型 | 命名格式 | 示例 |
|------|----------|------|
| **页面** | `系统-模块-页面` | `订单-列表页`、`用户-个人中心` |
| **组件** | `类型-业务名` | `按钮-提交订单`、`弹窗-删除确认` |
| **连线** | `动作-目标页面` | `点击提交-订单详情`、`取消-返回列表` |

## 页面结构规则（每页必须包含）

### 通用必备区块

每个页面 swimlane 的**标注区顶部**必须有**页面说明卡片**，x 坐标在标注区范围内（移动端 x=400，Web x=1464）：

```
页面：[系统-模块-页面名]
用途：[一句话描述页面职责]
用户角色：[买家 / 商家 / 管理员 / ...]
主操作：[该页面最核心的一个操作]
跳转去向：[操作A → 目标页, 操作B → 目标页]
```

> **禁止**：将页面说明卡片放在 UI 区（x < UI宽），不得出现在导航栏下方或覆盖任何 UI 组件。

### 列表页必须包含四个区块

| 区块 | 说明 |
|------|------|
| **筛选区** | 搜索框 + 筛选条件（状态/时间/分类等），含"查询"和"重置"按钮 |
| **表格区** | 列标题行 + 至少 3 行示例数据，含复选框（如需批量操作） |
| **分页区** | 当前页/总页数、每页条数、上一页/下一页按钮 |
| **行操作区** | 每行右侧操作列：查看/编辑/删除等，危险操作用红色标注 |

**表格结构强制规范（最重要，禁止违反）：**

表格必须是真实的列式结构，每列数据独立绘制为单独的 mxCell：

```
列标题行（height=44）：
  [复选框列 w=32] [订单编号 w=120] [客户名称 w=100] [金额 w=80] [状态 w=80] [操作 w=100]

数据行（height=52，至少3行）：
  [□] [YYG-2024-001] [渔港食品有限公司] [¥1,280] [已发货▸tag] [查看][处理]
  [□] [YYG-2024-002] [海鲜餐厅采购部]   [¥860]  [待付款▸tag] [查看][催付]
  [□] [YYG-2024-003] [冻品批发商行]     [¥3,200] [已完成▸tag] [查看]
```

**严禁做法（以下均为错误）：**
- 用单行文本卡片代替表格：`订单列表记录 1 | 编号 YYG-01 | 当前状态 正常`
- 所有列数据挤在同一个 mxCell 的 value 里
- 用竖排文字罗列数据项代替表格行
- 只画一个大圆角卡片容器，里面放文字行，没有列分隔

**正确做法：** 每列 = 独立 mxCell，列标题 y 坐标对齐，数据行 y 坐标对齐，同列所有单元格 x 和 width 完全一致。状态字段用 Tag 组件（带颜色背景），操作字段用 Button 组件。

### 表单页必须包含四个区块

| 区块 | 说明 |
|------|------|
| **字段区** | 所有输入字段，必填字段标注 `*`，每个字段旁注明校验规则 |
| **校验规则** | 在字段下方或右侧用灰色小字注明：如"最多 50 字"、"手机号格式" |
| **提交按钮** | 主按钮，注明点击后动作（tooltip 指向成功页或结果反馈） |
| **取消按钮** | 次要按钮，tooltip 指向来源页 |

### 详情页必须包含四个区块

| 区块 | 说明 |
|------|------|
| **基础信息区** | 核心字段展示（编号、名称、时间等键值对布局） |
| **状态区** | 当前状态标签 + 状态流转说明（如：待支付 → 已支付 → 已发货） |
| **操作区** | 该状态下可执行的操作按钮，不可用的按钮置灰并注明原因 |
| **日志/记录区** | 操作历史或流转记录列表（时间、操作人、操作内容） |

---

## 交互规则（所有页面强制执行）

| 规则 | 要求 |
|------|------|
| **主按钮动作说明** | 所有主按钮必须通过 `tooltip` 或旁注说明点击后的动作和跳转目标 |
| **危险操作确认弹窗** | 删除、清空、注销、强制操作等必须绘制确认弹窗，挂载到来源页面 |
| **表单反馈** | 每个表单页必须标注：成功态（提示文字 + 跳转）和失败态（错误提示位置） |
| **可回退** | 每个页面必须有明确的返回/取消路径，连线标注 `返回-[上级页面]` |

---

## 状态规则（必须补充，不得只画 happy path）

每个核心页面必须补充以下状态的示意（可在同一画布内并排展示）：

| 状态 | 说明 |
|------|------|
| **默认态** | 正常有数据的主流程状态 |
| **空态** | 无数据时的展示（引导文案 + 引导操作按钮） |
| **异常态** | 加载失败 / 网络错误（错误提示 + 重试按钮） |
| **无权限态** | 无访问权限时的提示（说明原因 + 返回操作） |
| **处理中态** | 提交/加载中的按钮禁用状态（按钮文字变"处理中..."） |
| **结果态** | 操作成功/失败的结果页或 Toast 提示 |

> 关键操作（提交、支付、删除）必须补充**处理中态**和**结果态**，其他页面至少补充**空态**和**异常态**。

## UI 渲染质量规则（禁止违反）

> **首要原则**：输出结果必须首先像界面，且必须达到 **UI 临摹级精度**——设计师拿到原型后可直接对照还原，不需要猜测尺寸和布局。

**临摹级精度要求：**
- 所有文字在 draw.io 默认缩放比（100%）下必须**清晰可读**，不得因组件过小而截断或溢出
- 组件尺寸必须使用规则三中的精确值，禁止随意估算
- 每个字段/按钮/标签必须是**独立的 mxCell**，不得多个元素合并为一个文本块
- 同类组件（所有输入框、所有主按钮）尺寸和样式必须完全一致

---

## 区块占位框禁止规则（最高优先级）

> 严禁用写区块名称的矩形框代替真实 UI 组件。区块名是 PRD 概念，不是界面元素。

**绝对禁止在 UI 区出现以下内容：**

| 禁止写法 | 正确替代 |
|---------|---------|
| 框内写"筛选/操作区" | 画 Input + Select + 查询Button + 重置Button |
| 框内写"表单区" | 画 Label+Input 逐行排列 |
| 框内写"数据区" | 画 Table（列标题行 + 数据行） |
| 框内写"内容区" | 画真实业务内容组件 |
| 框内写"导航栏" | 画蓝色背景矩形 + 白色文字的真实导航栏 |
| 框内写"底部标签栏" | 画白色背景 + 4个Tab项（图标+文字）的真实TabBar |
| 框内写"操作区" | 画真实 Button 组 |
| "收货地址卡片"容器内为空 | 容器内画：收货人姓名(text h=32)+手机号(text h=32)+地址(text h=48) 三行独立 mxCell |
| "商品摘要"容器内为空 | 容器内画：图片占位(w=64 h=64)+商品名(text)+规格(text)+数量×价格(text) |
| "金额明细"容器内为空 | 容器内画：运费/优惠/合计等每行键值对 mxCell（label在左，数字在右） |
| 字段 value 写"字段一/字段二/字段三" | 必须写真实业务字段名（如"品类名称"、"收货人"），来自需求文档 |
| value 写"列表项1/列表项2/数据项N/卡片N" | 必须写真实业务内容（如"优化用户登录流程"、"¥1,280"），禁止序号占位 |
| value 写"真实字段/示例数据/业务卡片" | 禁止将字段规格说明当作 value 填入，必须填实际的业务示例内容 |

**各区块正确画法（必须严格执行）：**

**筛选区（列表页顶部，水平排列）：**
- `[Input h=44 w=180 "关键词"]` `[Select h=44 w=140 "状态"]` `[DatePicker h=44 w=200 "时间范围"]` `[Button h=44 w=80 "查询" 蓝底白字]` `[Button h=44 w=80 "重置" 白底蓝字]`
- 所有组件 y 坐标一致，间距 12px

**表单字段（逐行排列）：**
- 每行：`[Label h=44 w=100 "字段名"]` + `[Input h=44 w=320 "请输入"]`，行间距 16px
- 必填字段在 Label 文字末尾加红色 `*`

**登录页（独立页面，无任何导航）：**
- 居中卡片 `w=360（移动端320）`，内含输入框组 + 主按钮，**上方无导航栏，左侧无侧边栏**
- 第一个元素：Logo 或产品名文字（h=60），然后输入框，最后按钮

**后台侧边栏（仅限后台非登录页）：**
- 深色矩形 `w=200 fillColor=#263238`，内含菜单项（每项 h=48，激活项 fillColor=#1e88e5）

### 规则一：先识别页面类型，再套用对应骨架

生成前必须判断页面类型，并强制套用对应骨架：

| 页面类型 | 识别特征 | 对应骨架 |
|----------|----------|----------|
| **列表页** | 有查询/筛选/表格/分页 | 顶部筛选区 + 表格 + 分页 + 行操作 |
| **表单页** | 有填写/提交/新增/编辑 | 字段分组 + 校验提示 + 提交/取消按钮 |
| **详情页** | 有查看/详情/信息展示 | 基础信息卡 + 状态标签 + 操作按钮 + 日志区 |
| **登录/注册页** | 有账号/密码输入，或资料明确要求短信/图形验证码 | 居中卡片 + 输入框组 + 主按钮 + 辅助链接 |
| **首页/Dashboard** | 有汇总数据/快捷入口 | 顶部统计卡 + 图表区 + 快捷操作入口 |
| **设置页** | 有配置项/开关/保存 | 左侧导航 + 右侧设置分组 + 保存按钮 |

---

### 规则二：需求信息映射为 UI 组件

**登录页例外规则：**

- 后台登录页属于**未登录态独立页面**，禁止复用后台首页/列表页的左侧菜单、顶部业务导航、面包屑。
- 登录页默认仅展示完成登录所必需的字段。**验证码/校验码不是默认组件**，只有产品资料明确要求时才允许出现。
- 如果资料仅写"后台登录"，默认按 **账号 + 密码 + 登录按钮 + 忘记密码/帮助链接** 生成，不得自行补充菜单和验证码。

| 需求内容 | 正确做法 | 禁止做法 |
|----------|----------|----------|
| 状态字段（待支付/已支付/...） | Tag 标签组件，不同颜色区分状态 | 大文本框写"状态：待支付" |
| 列表数据 | Table 组件，每列独立 mxCell，列标题行 + 3 行示例数据，每行每列单独绘制 | 单行文本卡片（"记录N\|编号XX\|状态YY"）；所有列数据挤在一个 mxCell |
| 筛选条件 | Input + Select + DatePicker + Button | 说明框写"筛选区：支持按状态筛选" |
| 操作按钮组 | Button 组件，主次样式区分 | 文字写"操作：查看、编辑、删除" |
| 弹窗/确认框 | Modal 浮层组件（绘制在主页面旁） | 大框写"此处弹出确认弹窗" |
| 分页 | Pagination 组件（含页码 + 条数） | 文字写"底部有分页" |
| Tab 切换 | Tab 组件，多个 Tab 标签 | 说明框写"支持按Tab切换" |

---

### 规则四：页面骨架隔离（禁止跨类型复用导航）

> **根本原则**：骨架由**页面类型**决定，不由**系统类型**决定。同一个后台系统里，登录页和列表页是不同类型，必须用不同骨架。

**独立页面**（以下类型必须是全屏独立页面，严禁出现侧边栏/顶部业务导航/面包屑）：

| 独立页面类型 | 识别关键词 | 正确骨架 |
|------------|-----------|---------|
| 登录页 / 注册页 | 登录、注册、Sign in、注册账号 | 居中卡片，无任何导航 |
| 落地页 / 欢迎页 | 首页入口、欢迎、Landing | 全宽背景 + 居中内容，无侧边栏 |
| 错误页 | 404、无权限、服务异常 | 居中插图 + 文案 + 返回按钮，无导航 |
| 支付结果页 | 支付成功、下单完成、支付失败 | 居中结果卡片，无侧边栏 |

**自查要求**：生成每个页面前，先判断：该页面是否属于独立页面类型？若是，立即去掉一切导航组件再开始绘制。

---

### 规则五：多模式互斥展示（禁止堆叠所有方式）

> **根本原则**：需求说"支持 A 和 B 两种方式"，界面同一时刻**只展示一种**。用 Tab 或切换按钮让用户选择，不得把两种方式的字段同时平铺。

**触发关键词**（出现以下词时必须用 Tab/切换，不得平铺）：

- 支持 X 和 Y 两种登录/查询/支付/操作方式
- 可选 A 或 B
- 多种方式、两种模式、切换方式

**正确做法对照：**

| 需求描述 | 正确做法 | 禁止做法 |
|---------|---------|---------|
| 支持账号密码和手机验证码两种登录 | Tab「账号登录」/「验证码登录」，每个 Tab 只显示对应字段 | 账号+密码+手机号+验证码全部放在同一表单 |
| 支持微信支付和银行卡两种支付 | Tab「微信支付」/「银行卡」，切换后只显示对应字段 | 微信二维码和银行卡输入框同时展示 |
| 支持快递和自提两种配送方式 | 单选切换「快递」/「自提」，切换后只显示对应地址输入区 | 收货地址和自提门店选择同时展示 |

**Tab 组件规格（draw.io）**：
- Tab 栏高度 40px，每个 Tab 标签宽度等分，激活态用主色底色 + 白色文字
- 同一 swimlane 内绘制默认激活的第一个 Tab 的内容，其余 Tab 内容在标注区注明"切换后显示 [字段列表]"
