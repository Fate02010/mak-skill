# Step 7：审视检查，提出改进建议

**目标：** 全面审视 SQL，提出改进建议；设计影响领域模型时必须同步更新 `领域模型.md`。

## 阶段 7-1：五维度审视

读取 `WORK_DIR/[产品名称].sql` 和 `WORK_DIR/领域模型.md`：

| 维度 | 检查要点 |
|------|---------|
| **完整性** | 领域模型实体都有对应表？多对多有中间表？缺少日志/流转记录表？ |
| **规范性** | 所有表名有 `t_` 前缀？每字段有 COMMENT？主键 BIGINT？公共字段一致？ |
| **性能** | WHERE/JOIN 字段有索引？大字段考虑分离？大表考虑分区策略？ |
| **业务正确性** | 字段类型长度合理？枚举值在 COMMENT 说明？唯一约束覆盖业务要求？ |
| **领域模型一致性** | 表结构与领域模型一致？Step 6 的领域模型反馈已处理？ |

## 阶段 7-2：展示审视结果，等待确认

```
=== 数据库设计审视报告 ===

【完整性】✅ / ⚠️ [问题描述]
【规范性】✅ / ⚠️ [问题描述]
【性能】✅ / ⚠️ [建议描述]
【业务正确性】✅ / ⚠️ [问题描述]
【领域模型一致性】✅ / ⚠️ [需更新说明]

是否应用改进建议？（"全部应用" / "选择应用 1,3" / "不需要"）
```

## 阶段 7-3：应用改进

修改 `WORK_DIR/[产品名称].sql`。

## 阶段 7-4：同步更新相关文档

**如影响领域模型**：更新 `领域模型.md`（实体列表、关系总览），变更记录追加：
`| v1.1 | [变更摘要] | SQL 审视阶段发现 |`

**如新增/删除表或关系/索引变更**：
- 更新 `ER关系图.md`（Mermaid 图、关系汇总表、索引表）
- 更新 `数据详细设计文档.md`：新增/删除表的字段章节、业务规则、数据字典状态码，并在变更记录中追加一行

## 阶段 7-5：完成报告

```
=== 数据库设计完成 ===
- [WORK_DIR]/[产品名称].sql        （共 N 张表）
- [WORK_DIR]/ER关系图.md           （[已更新 / 无变化]）
- [WORK_DIR]/数据详细设计文档.md   （[已更新 / 无变化]）
- [WORK_DIR]/领域模型.md           （v[X]，[已更新 / 无变化]）
如需增量调整，下次启动选择 Step 8 增量模式。
```

## 改进循环

用户可继续提出改进需求，每轮改进后同步更新 SQL / 领域模型 / ER 关系图；用户回复"完成"或"不需要"时终止。
