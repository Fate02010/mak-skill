# 数据详细设计文档生成规范

**目标：** 基于已生成的 SQL 和领域模型，生成面向开发团队的 `数据详细设计文档.md`，清晰描述每张表的字段定义、业务规则和关联关系。

## 生成步骤

1. 读取 `WORK_DIR/[产品名称].sql` 提取所有表和字段信息
2. 读取 `WORK_DIR/领域模型.md` 补充聚合和业务规则说明
3. 读取 `WORK_DIR/ER关系图.md` 引用关系说明
4. 按以下格式生成 `WORK_DIR/数据详细设计文档.md`

## 数据详细设计文档.md 格式

```markdown
# [产品名称] 数据详细设计文档

| 项目 | 内容 |
|------|------|
| 产品名称 | [产品名称] |
| 目标数据库 | [所选数据库] |
| 文档版本 | v1.0 |
| 生成时间 | [日期] |
| 领域模型版本 | v[X] |
| 总表数 | [N] 张 |

---

## 一、设计概述

### 1.1 数据库选型

使用 **[所选数据库]**，原因：[结合产品特性的1-2句说明，如"读多写少、需要复杂关联查询，适合关系型数据库"]

### 1.2 命名规范

- 表名：`t_` 前缀 + 小写下划线（如 `t_order_item`）
- 字段：小写下划线（如 `create_time`）
- 索引：`idx_` / `uniq_` / `ft_` 前缀
- 主键：统一为 `id`，BIGINT 类型，兼容雪花算法

### 1.3 公共字段（所有表必含）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键，支持自增或雪花算法 |
| create_by | VARCHAR(64) | 创建人 |
| create_time | DATETIME | 创建时间，默认当前时间 |
| update_by | VARCHAR(64) | 最后更新人 |
| update_time | DATETIME | 最后更新时间，自动维护 |
| delete_flag | TINYINT(1) | 软删除标志（0=未删除，1=已删除） |

> 纯关联中间表不含 delete_flag，其余公共字段保留。

#### 2.1 t_user（用户表）

**用途：** 存储用户账号基本信息，是用户聚合的聚合根。

**字段说明：**

| 字段名 | 类型 | 长度 | 可空 | 默认值 | 说明 |
|--------|------|------|------|--------|------|
| id | BIGINT | — | 否 | — | 主键 |
| username | VARCHAR | 64 | 否 | — | 用户名，全局唯一 |
| password | VARCHAR | 128 | 否 | — | 密码（加密存储） |
| email | VARCHAR | 128 | 是 | NULL | 邮箱 |
| phone | VARCHAR | 20 | 是 | NULL | 手机号 |
| status | TINYINT | 1 | 否 | 1 | 状态（0=禁用，1=启用） |
| create_by | VARCHAR | 64 | 否 | '' | 创建人 |
| create_time | DATETIME | — | 否 | CURRENT_TIMESTAMP | 创建时间 |
| update_by | VARCHAR | 64 | 否 | '' | 更新人 |
| update_time | DATETIME | — | 否 | CURRENT_TIMESTAMP | 更新时间 |
| delete_flag | TINYINT | 1 | 否 | 0 | 删除标志 |

**索引：**

| 索引名 | 类型 | 字段 | 用途 |
|--------|------|------|------|
| PRIMARY | 主键 | id | — |
| uniq_username | 唯一 | username | 用户名唯一约束 |
| idx_email | 普通 | email | 邮箱查询 |

**业务规则：**
- 用户名创建后不可修改
- 密码需使用 BCrypt 加密存储，禁止明文
- 软删除：delete_flag=1 视为已注销，不可登录

**关联关系：**
- `t_user_address.user_id → t_user.id`（一对多，用户拥有多个地址）
- `t_order.user_id → t_user.id`（一对多，用户可创建多笔订单）

---

#### 2.2 t_user_address（用户地址表）

**用途：** 管理用户的收货地址信息。

**字段说明：**

| 字段名 | 类型 | 长度 | 可空 | 默认值 | 说明 |
|--------|------|------|------|--------|------|
| id | BIGINT | — | 否 | — | 主键 |
| user_id | BIGINT | — | 否 | — | 关联 t_user.id |
| receiver | VARCHAR | 64 | 否 | — | 收货人姓名 |
| phone | VARCHAR | 20 | 否 | — | 收货人手机号 |
| province | VARCHAR | 32 | 否 | — | 省份 |
| city | VARCHAR | 32 | 否 | — | 城市 |
| district | VARCHAR | 32 | 否 | — | 区县 |
| detail | VARCHAR | 256 | 否 | — | 详细地址 |
| is_default | TINYINT | 1 | 否 | 0 | 是否默认地址（0=否，1=是） |
| ...公共字段 | | | | | |

**索引：**

| 索引名 | 类型 | 字段 | 用途 |
|--------|------|------|------|
| PRIMARY | 主键 | id | — |
| idx_user_id | 普通 | user_id | 按用户查地址 |

**业务规则：**
- 每个用户最多保存 20 条地址
- 同一用户只能有一条默认地址，新设默认地址时自动取消旧默认
```

## 注意事项

- 字段说明直接从 SQL COMMENT 提取，确保一致性
- 业务规则从领域模型和产品资料中提炼，不可遗漏状态流转说明
- 跨表流程至少覆盖产品的 2-3 个核心业务流程
- 数据字典的状态码必须与 SQL COMMENT 枚举值保持一致
- 文档在 Step 7 审视改进后、Step 8 增量变更后需同步更新
