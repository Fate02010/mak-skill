# Step 6：并行生成 SQL 文件

**目标：** 按 Step 5 拆分的任务，并行生成各聚合的 SQL 建表文件，最后合并为完整 SQL 文件。

## 执行步骤

### 阶段 6-1：判断生成方式

读取 `WORK_DIR/db_task_list.md`：

- **任务数 ≤ 1（表数 ≤ 10）**：顺序生成，直接写入最终 SQL 文件
- **任务数 > 1**：并行生成，每个任务生成独立临时文件后合并

### 阶段 6-2A：顺序生成（表数 ≤ 10）

1. Read `SKILL_DIR/steps/step4-sql-rules.md` 获取 SQL 规范
2. 读取 `WORK_DIR/领域模型.md` 和相关资料
3. 按聚合顺序生成全部建表 SQL
4. 直接写入 `WORK_DIR/[产品名称].sql`

### 阶段 6-2B：并行生成（表数 > 10）

**Claude Code 方式（使用 Agent 工具）：**

为每个任务启动独立 Agent，子 Agent prompt 模板：

```
你是 [产品名称] 的数据库架构师（来自 Step 3 的角色设定）。

任务：生成 [聚合名称] 的建表 SQL

请按顺序执行：
1. Read `[SKILL_DIR]/steps/step4-sql-rules.md` 获取 SQL 规范（必须）
2. Read `[WORK_DIR]/领域模型.md` 获取实体定义
3. Read `[WORK_DIR]/RountMap.md` 找到 [聚合名称] 相关的核心资料文件路径
4. 读取相关资料文件，理解字段需求
5. 生成以下表的 SQL（严格遵循 step4-sql-rules.md 规范）：
   - [表1]：[职责描述]
   - [表2]：[职责描述]
   ...
6. 将生成的 SQL 写入 `[WORK_DIR]/sql_[聚合英文名].sql`

注意：
- 严禁写入 /private/tmp 或其他系统临时目录
- 每个字段必须有 COMMENT
- 主键使用 BIGINT，兼容雪花算法
- 如发现领域模型有误或遗漏，在 sql 文件末尾追加注释：
  -- [领域模型反馈] 发现 XXX 问题，建议 YYY
```

**Codex 方式（使用 Task 工具）：**

为每个任务调用 Task（run_in_background=true），参数与上述 prompt 相同，生成完成后用 TaskOutput 收集结果。

### 阶段 6-3：合并 SQL 文件

所有子任务完成后：

1. 按聚合依赖顺序读取各临时文件（被依赖的聚合表先写入）
2. 合并顺序：基础字典表 → 用户聚合 → 商品聚合 → 订单聚合 → 关系表 → 其他
3. 写入 `WORK_DIR/[产品名称].sql`，文件头包含：

```sql
-- ============================================================
-- [产品名称] 数据库建表脚本
-- 目标数据库：[所选数据库]
-- 生成时间：[日期]
-- 领域模型版本：v[X]
-- ============================================================
```

4. 合并完成后删除临时文件（`sql_*.sql`）

### 阶段 6-4：生成 ER 关系说明文档

SQL 合并完成后，读取最终 SQL 文件，生成 `WORK_DIR/ER关系图.md`。

Read `SKILL_DIR/steps/step6-er-doc.md` 获取 ER 文档格式规范并生成。

### 阶段 6-5：生成数据详细设计文档

Read `SKILL_DIR/steps/step6-design-doc.md` 获取详细设计文档格式规范，生成 `WORK_DIR/数据详细设计文档.md`。

该文档包含：
- 设计概述（数据库选型、命名规范、公共字段说明）
- 每张表的字段明细表、索引表、业务规则、关联关系
- 跨表核心业务流程说明
- 数据字典（状态码汇总）

### 阶段 6-6：收集领域模型反馈

扫描各临时文件中的 `[领域模型反馈]` 注释，汇总后告知用户：

```
=== SQL 生成完成 ===

输出文件：
  - [WORK_DIR]/[产品名称].sql      （共 [N] 张表）
  - [WORK_DIR]/ER关系图.md
  - [WORK_DIR]/数据详细设计文档.md

[如有领域模型反馈]
⚠️  生成过程中发现以下领域模型问题，Step 7 将评估是否更新：
- 订单聚合：发现缺少退款表，建议新增 order_refund
```

进入 Step 7 进行审视与改进。
